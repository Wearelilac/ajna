# B1.1 API Setup Instructions

This B1.1 skeleton is production-ready code but requires Node package installation, which can timeout on slow connections. This document explains the setup.

## Quick Start (Local Development)

### Prerequisites
- Node.js 20+
- npm or yarn
- PostgreSQL 16+
- Redis 7+

### Environment Setup

```bash
cd apps/api
cp .env.example .env

# Generate KEK (32 bytes in base64)
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))" 

# Update .env with:
# - AJNA_KEK_BASE64=<generated key>
# - AJNA_JWT_SECRET=dev-secret-change-in-prod
# - DATABASE_URL=postgres://localhost/ajna
# - REDIS_URL=redis://localhost:6379
```

### Install & Build

```bash
npm install

# Type check
npm run type-check

# Lint
npm run lint

# Build
npm run build

# Tests
npm test

# Generate OpenAPI contract
npm run contract:generate
```

### Run

```bash
npm run dev        # Development with watch
npm start          # Production mode
npm run contract:check  # Verify contract is up-to-date
```

## Code Architecture

### 1. Environment Validation
- `common/config.ts`: Zod schema with required vars
- **Behavior:** Exits with error names (no values) if vars missing
- **Test:** `config.spec.ts` verifies exit on missing vars

### 2. Standard Error Shape
- **All endpoints return:** `{ statusCode, error, code, message, requestId }`
- **Error codes:** Listed in `common/errors.ts`, stable UPPER_SNAKE
- **Test:** `exception-filter.spec.ts` tests 10 error paths

### 3. Request IDs
- Accept valid UUID from `x-request-id` header or generate one
- **Attach to:** Logs, response headers
- **Test:** Roundtrip tests verify valid IDs pass, invalid IDs are replaced

### 4. Structured Logging
- `pino` with automatic redaction of PHI, tokens, audio data
- **Redaction paths:** PHI (email, phone, metrics), audio, tokens, keys
- **Test:** `logger.spec.ts` verifies patterns not logged

### 5. Rate Limiting
- Default: 60 req/min per IP (Fastify rate-limit plugin)
- Per-route overrides supported (add decorator in feature endpoints)
- **Error:** 429 RATE_LIMIT_EXCEEDED

### 6. Health Endpoints
- `GET /v1/health`: Liveness (always returns unless crashed)
- `GET /v1/ready`: Readiness (checks DB/Redis connectivity, returns degraded flags)
- **Contract:** Listed in `contracts/openapi.v1.yaml`

### 7. OpenAPI / Swagger
- Generated by `@nestjs/swagger` decorator metadata
- Write contract: `npm run contract:generate`
- Verify contract: `npm run contract:check` (CI validates)
- Schema: Shared `ErrorResponse`, `bearerAuth` security (used by B1.3)

### 8. Limits Registry
- `common/limits.ts`: All P0 findings (wearable, baseline, acoustic, etc.)
- **Purpose:** Read by B2.1, B2.2, M3.1, M3.2 as shared config
- **Example:** `LIMITS.BASELINE.MIN_VALID_DAYS = 14`

## Deployment

### Render (render.yaml)

```bash
# Configure env secrets in Render dashboard:
# - AJNA_KEK_BASE64
# - AJNA_JWT_SECRET
# - AJNA_SCORING_TOKEN
# - DATABASE_URL (auto-linked)

git push origin master
```

### Local Docker (optional)

```bash
docker build -t ajna-api .
docker run -p 3000:3000 \
  -e DATABASE_URL=postgres://... \
  -e REDIS_URL=redis://... \
  -e AJNA_KEK_BASE64=... \
  ajna-api
```

## CI/CD (.github/workflows/api.yml)

Runs on push/PR:
1. Type check: `npm run type-check`
2. Lint: `npm run lint`
3. Build: `npm run build`
4. Tests: `npm test` (with coverage)
5. Contract check: `npm run contract:check` (fails if stale)
