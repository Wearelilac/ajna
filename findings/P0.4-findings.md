### Test 6: Review State Machine

```
Legal transitions: 8/8 passed
Illegal transitions: 7/7 correctly blocked
```

**Legal transitions:**
```
draft → in_review (any role)
in_review → approved | edited_approved | rejected (reviewer only)
approved → closed (any role)
edited_approved → closed (any role)
rejected → closed | in_review (any role, can re-review after edits)
```

**Illegal transitions (correctly blocked):**
```
draft → approved (must go through in_review first)
draft → rejected
draft → closed
in_review → closed (must approve/reject first)
approved → in_review (can't un-approve)
closed → in_review (terminal state)
in_review → approved with role='staff' (only reviewer/clinical_supervisor can approve)
```

**Audit chain:** Every transition is recorded in `draft_reviews` table with:
- reviewer_id, reviewer_role
- from_status, to_status
- reason (optional)
- edited_body (if edits made)
- prev_hash (SHA-256 of previous review)
- row_hash (SHA-256 of this review)

This hash-chained audit log is immutable and detects tampering.

### Test 7: No Messaging Provider Imports

**Production safety:** B4.2 and W4.2 must maintain this separation. Approval workflow ≠ sending workflow. A separate, audited "outreach delivery" service (out of scope for v1) would consume approved drafts.

## Routing Algorithm

**Step 1: Hard eligibility filters**
1. Age band match (required)
2. Indicator type match (e.g., overdue_screening, frequent_flags)
3. Screening type match (e.g., well_child_18m)
4. Overdue window check (days_overdue ≤ max_days_overdue)
5. Flag count check (flag_count ≥ min_flag_count)

**Step 2: Vector similarity**
1. Generate gap embedding from indicator_summary (in production: all-MiniLM-L6-v2)
2. Compute cosine similarity with all eligible pathways
3. Sort by similarity (descending)
4. Return top-k (default k=3)

**Step 3: No suitable pathway**
If no pathways pass eligibility filters OR similarity < threshold, return empty list and flag case for manual review.

**Performance (production estimate):**
- Eligibility filter: <1ms (JSONB GIN index)
- Vector search (HNSW): 1-2ms (top-100 recall >95%)
- Total routing time: 2-3ms per gap

## Risks & Mitigations

### Risk 1: Low Overdue Detection Rate (52%)

**Risk:** Strict eligibility matching (days_overdue ≤ max_days_overdue) causes 48% of overdue cases to be suppressed.

**Mitigation:**
- Add "grace period" (+30-60 days) beyond max_days_overdue
- Flag "very overdue" cases (>180 days) for high-priority manual review
- Expand pathway eligibility windows (e.g., 18-month well-child visit: 60 days → 90 days)

**Status:** Acceptable for v1. Monitor in production and adjust windows based on staff feedback.

### Risk 2: Template-Only Drafts Feel Impersonal

**Risk:** Staff or members may find template drafts too generic.

**Mitigation:**
- Start with templates (proven safe, fast, free)
- Collect staff feedback in first 90 days
- If needed, add opt-in LLM polish with:
  - Strict input constraints (approved snippets only)
  - Mandatory post-generation lint
  - Auto-reject on banned-wording violation
  - Record llm_model in outreach_drafts table

**Status:** Acceptable. Template-only is the safe starting point.

### Risk 3: State Machine Complexity

**Risk:** 6-state machine with role-based transitions may confuse staff.

**Mitigation:**
- W4.2 (review console) shows available actions only (hide illegal transitions)
- Add tooltips explaining why certain actions are disabled
- Provide training doc with state diagram

**Status:** Acceptable. State machine enforces required review step (no auto-approve).

   - `loadPathways()` - seed 20 pathways from P0.4
   - `generateEmbeddings()` - use all-MiniLM-L6-v2 (or sentence-transformers API)

3. **Create CareGapService**
   - `detectOverdue(subject_id)` - query care_history + schedules
   - `detectFrequentFlags(subject_id)` - query population_flags (from P0.3)
   - `detectLowPRI(subject_id)` - query community_pri_monthly (from P0.3)
   - `createGap(subject_id, gap_type, indicator_summary)` - insert into care_gaps

4. **Create RoutingService**
   - `routeGap(care_gap_id, top_k=3)` - apply eligibility filters + vector search
   - `recordMatches(care_gap_id, matches)` - insert into pathway_matches

5. **Create OutreachDraftService**
   - `generateDraft(care_gap_id, pathway_id)` - template-only for v1
   - `lintDraft(body)` - banned-wording check (reject on violation)
   - `createDraft(care_gap_id, pathway_id, body)` - insert with status='draft'

6. **Create ReviewService**
   - `transitionStatus(draft_id, to_status, reviewer_id, reason?, edited_body?)` - validate state machine + insert draft_reviews with hash chain
   - `getAuditChain(draft_id)` - return all reviews for draft
   - `verifyChain(draft_id)` - recompute hashes, detect tampering

7. **Create endpoints**
   - POST /v1/care-gaps/detect (run overdue + flags + PRI detection for subject)
   - GET /v1/care-gaps/:id/matches (return top-k pathway matches)
   - POST /v1/outreach-drafts (generate draft from gap + pathway)
   - PATCH /v1/outreach-drafts/:id/review (transition status, record review)

8. **Add RLS policies**
   - app_official: SELECT on care_gaps, pathway_matches, outreach_drafts (filtered by subject consent)
   - app_official: INSERT on draft_reviews (reviewer role only)
