## Summary

Implemented monitor session management, de-identified flag ingest with 7-field allow-list enforcement, and human-workflow crisis review queue with state machine validation. All endpoints enforce RLS, consent-gating, and audit trails. **NO audio, NO transcript, NO precise location, NO automatic external actions.**

## Implementation

### Database Schema (`apps/api/src/db/monitor.schema.sql`)
- **monitor_sessions**: Session metadata (NO audio), 600-second cap, consent-gated
- **deidentified_flags**: 7-field allow-list ONLY (signature, confidence, time_bucket, model_version, session_duration_sec, energy_db), 30-day retention
- **crisis_reviews**: Human workflow queue, state machine (new → assigned → in_review → closed)
- **crisis_review_events**: Audit trail with hash-linked chain for immutability

### RLS Policies
| Table | app_user | app_worker | app_reviewer | app_official |
|-------|----------|------------|--------------|--------------|
| monitor_sessions | Read/write own | Read all | Deny | Deny |
| deidentified_flags | **DENY** (de-identified) | Write only | Read all | Deny |
| crisis_reviews | Deny | Deny | Read/write | **DENY** |
| crisis_review_events | Deny | Deny | Read/write | Deny |

### Services
1. **MonitorService** (`apps/api/src/monitor/monitor.service.ts`)
   - `startSession()`: Creates/reuses session, returns server-side `maxDurationSec` (600)
   - `endSession()`: Closes session with reason (user_stopped, timeout, consent_revoked)
   - `getActiveSession()`: Returns open session or null if expired
   - `storeFlag()`: 7-field allow-list validation, truncates `time_bucket` to hour server-side
   - `handleConsentRevoked()`: Ends open sessions, deletes all flags for subject

2. **CrisisService** (`apps/api/src/monitor/crisis.service.ts`)
   - `createOrUpdateReview()`: Groups repeated flags within 24-hour rolling window
   - `listReviews()`: Filters by state, owner, escalation status
   - `getReview()`: Returns review with de-identified flags (NO subject_id unless revealed)
   - `assignReview()`: Assigns to Reviewer, records audit event
   - `transitionReview()`: State machine validation, requires outcome for closed state
   - `revealContact()`: Returns subject_id + emergency contact, writes audit trail
   - `verifyChain()`: Validates hash-linked audit chain integrity
   - `escalateUnassigned()`: Flags reviews past SLA (notifies staff, NOT user)

### State Machine
```
new → assigned → in_review → closed (terminal)
     ↑           ↑
     └───────────┘ (can reassign/unassign)
```

**Outcomes** (required for closed state):
- `no_action`
- `routine_follow_up_requested`
- `escalated_to_clinical_lead`

### Controllers
1. **MonitorController** (`apps/api/src/monitor/monitor.controller.ts`)
   - `POST /v1/monitor/sessions`: Start session (consent-gated)
   - `POST /v1/monitor/sessions/:id/end`: End session with reason
   - `GET /v1/monitor/sessions/active`: Get active session
   - `POST /v1/monitor/flags`: Store flag (7-field allow-list check)

2. **CrisisController** (`apps/api/src/monitor/crisis.controller.ts`)
   - `GET /v1/crisis-reviews`: List with filters (state, owner, escalatedToLead)
   - `GET /v1/crisis-reviews/:id`: Detail view with flags
   - `POST /v1/crisis-reviews/:id/assign`: Assign to Reviewer
   - `POST /v1/crisis-reviews/:id/transition`: State transition with validation
   - `POST /v1/crisis-reviews/:id/reveal-contact`: Reveal identity with audit reason

### Workers

  - Job: `ajna.monitor.flag-retention`
  - Deletes flags older than 30 days
  - Crisis review records keep aggregated counts and outcome

- `MONITOR_SESSION_REQUIRED`: No session found
- `MONITOR_SESSION_EXPIRED`: Session past 600-second cap

## Architecture Notes

1. **7-Field Allow-list (Strict)**: Unknown fields rejected at controller level before DB insert. NO audio, NO transcript, NO features, NO precise location, NO device_id.

2. **Time Bucket Truncation**: Always server-side (hour precision). Client-submitted value is rounded, never trusted.

3. **State Machine**: Enforced in `CrisisService.transitionReview()`. Legal transitions defined in `STATE_MACHINE` constant. Closed is terminal state.

4. **Audit Chain**: Hash-linked trail for immutability. Each event includes `prev_hash`, computed from previous event's `row_hash`. `verifyChain()` detects tampering.

5. **De-identification**: Users cannot read their own flags (RLS denies app_user). Reviewers see flags without subject_id until `reveal-contact` is used with audit reason.

6. **Crisis Review Grouping**: Repeated flags within 24-hour window update existing review (increment `flag_count`, update `last_flag_at`). No duplicate reviews.

7. **Consent Revocation**: Cleanup is immediate and permanent. All flags deleted, open sessions closed with reason. No recovery path.

8. **SLA Escalation**: Flags unassigned reviews, does NOT trigger automatic outbound message. Staff notification only (to be implemented in W3.1).

9. **NO Automatic Actions**: No automatic dispatch, no emergency calls, no SMS/email to users. Review queue is human-workflow only.
