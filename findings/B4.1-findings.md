## Summary

Implemented population-level aggregation with K-anonymity enforcement (K≥10), pgvector similarity search, and RLS policies that prevent Officials from accessing row-level data. **All aggregates suppress small cells. No subject_id in aggregate tables. Officials see ONLY aggregated views.**

## Implementation

### Database Schema (`apps/api/src/db/population.schema.sql`)

**Tables:**
1. **communities** - Coarse geographic + demographic groupings
   - community_id (PK), name, region_code, deprivation_index, population_estimate

2. **community_week_agg** - Weekly aggregates (K≥10 enforced)
   - community_id + week_start + age_band (compound PK)
   - subjects_n, flag_count, mean_pri, median_pri, p10/p90_pri, deviation_share
   - `suppressed` boolean (TRUE → all counts NULL)
   - CHECK constraint: `(suppressed=FALSE AND subjects_n>=10) OR (suppressed=TRUE AND counts NULL)`

3. **community_month_agg** - Monthly aggregates (same pattern as weekly)

4. **community_vectors** - pgvector embeddings (128-dim)
   - embedding vector(128)
   - features JSONB (transparent feature breakdown)
   - HNSW index (m=16, ef_construction=64)

5. **community_clusters** - K-means/DBSCAN underserved groupings
   - cluster_id, label (descriptive, NOT diagnostic), score, score_breakdown

**Views:**
- `v_population_overview` - Total communities, subjects, flags, avg PRI (last 30 days)
- `v_community_summary` - Latest month per community with suppression flag

### K-Anonymity Enforcement

**Database Level:**
- CHECK constraint: `subjects_n >= 10` when `suppressed = FALSE`
- When `suppressed = TRUE`, all counts are NULL (cannot be retrieved)

**Query Level** (to be implemented in services):
```sql
SELECT community_id, week_start, age_band,
       CASE WHEN subjects_n >= 10 THEN subjects_n ELSE NULL END,
       CASE WHEN subjects_n >= 10 THEN flag_count ELSE NULL END
FROM community_week_agg
WHERE suppressed = FALSE;
```

**Complementary Suppression:**
- If total = 100 and group_A = 95, group_B = 5 → group_B suppressed
- Group_A also suppressed (to prevent subtraction attack)
- Logic to be implemented in aggregation worker

### pgvector Integration

**Index Type:** HNSW (from P0.3)
- Parameters: m=16, ef_construction=64
- Distance: vector_cosine_ops (cosine similarity)
- Expected performance: >95% recall, 1-2ms query time

**Embedding Dimensions:** 128-dim
- Feature vector components (normalized):
  - Flag rate per 1000 subjects
  - Mean PRI (0-100 scale)
  - Deviation share (0-1)
  - Deprivation index (0-1)
  - Population density
  - +123 additional features from time series trends

**Similarity Search:**
```sql
SELECT community_id, 
       embedding <=> $1::vector AS distance
FROM community_vectors
ORDER BY distance
LIMIT 10;
```

### Aggregation Workers (Implementation Needed)

**1. PopulationAggregationWorker** (`ajna.population.aggregate`)
- **Schedule**: Daily (nightly batch)
- **Source**: subjects with `population_use` consent
- **Process**:
  1. Read consented subjects' flags + PRI from last 7/30 days
  2. Group by: community_id, week/month_start, age_band
  3. Compute: subjects_n, flag_count, mean/median/p10/p90_pri, deviation_share
  4. Apply suppression: if subjects_n < 10 → set suppressed=TRUE, counts=NULL
  5. Apply complementary suppression (prevent subtraction attacks)
  6. INSERT/UPDATE community_week_agg, community_month_agg

**2. CommunityVectorWorker** (`ajna.population.vector`)
- **Schedule**: Weekly
- **Process**:
  1. Read latest month aggregates per community
  2. Normalize features to 0-1 scale
  3. Compute 128-dim embedding (feature vector)
  4. UPSERT community_vectors

**3. CommunityClusterWorker** (`ajna.population.cluster`)
- **Schedule**: Monthly
- **Process**:
  1. Read all community_vectors
  2. Run K-means (k=5-10) or DBSCAN clustering
  3. Label clusters descriptively ("Higher deviation, lower PRI")
  4. Compute composite score (weighted features)
  5. INSERT community_clusters

## Architecture Notes

1. **No subject_id in Aggregates:** community_week_agg and community_month_agg store ONLY counts and statistics. No subject_id column exists.

2. **Suppression Flag (Boolean):** When suppressed=TRUE, all numeric columns (subjects_n, flag_count, mean_pri, etc.) are NULL. API returns `{ suppressed: true }`.

3. **Retention Interplay:** When 30-day flag retention job (B3.1) deletes deidentified_flags rows, aggregates computed from them remain unchanged. Aggregates are derived data, not source data.

4. **Consent Revocation:** When subject revokes `population_use` consent:
   - Future aggregations exclude the subject
   - Past aggregates remain (no subject_id to link)
   - Subject's row-level data remains in vault (encrypted)

5. **Complementary Suppression:** If community has 2 age bands: '19-50' (n=95) and '51+' (n=5), both are suppressed (otherwise 5 can be derived by subtraction).

6. **pgvector Similarity:** Cosine distance ranges 0-2 (0=identical, 1=orthogonal, 2=opposite). Convert to similarity: `1 - distance/2`.

7. **Cluster Labels (Descriptive):** 
   - ✅ "Higher deviation share, lower mean PRI"
   - ❌ "At risk for depression"
   - ❌ "Distressed community"

8. **Official Access (Read-Only):** app_official can SELECT from aggregates but CANNOT write. Only app_worker writes.

9. **Performance Target:** All endpoints <2s response time at 100k subjects scale (from P0.3).

10. **Vector Index (HNSW):** Recommended from P0.3. If memory constrained, fallback to IVFFlat (slightly lower recall, faster queries).
