## Summary

Implemented staff-facing crisis review console: queue table with filters, detail page with state machine actions, reveal-contact guarded modal, and safety notices. **NO automatic actions. NO outbound contact capabilities. Advisory workflow for human Reviewers only.**

## Implementation

### Architecture (`apps/web/src/features/crisis-reviews/`)

**Pages:**
1. **ReviewQueuePage** - `/review` table with filters, sorting, auto-refresh (30s)
2. **ReviewDetailPage** - `/review/[id]` detail view with actions

**Components:**
1. **ReviewQueueTable** - Table (state, owner, flags, last flag, age, SLA)
2. **ReviewFilters** - State, owner, escalation filters
3. **ReviewHeader** - Review summary + revealed contact display
4. **FlagTimeline** - De-identified flags grouped by hour bucket
5. **ActionButtons** - Legal transitions based on state machine
6. **RevealContactModal** - Guarded (requires reason ≥20 chars + confirmation)
7. **TransitionModal** - Record outcome when closing (required)
8. **StateHistory** - Audit trail placeholder (requires backend integration)
9. **SafetyNotice** - "Advisory indicators for human review. Not a diagnosis."

**Hooks:**
1. **useCrisisReviews** - List with filters (GET /v1/crisis-reviews)
2. **useCrisisReview** - Single review with flags (GET /v1/crisis-reviews/:id)
3. **useCrisisActions** - Assign, transition, reveal contact

**API Client (`api.ts`):**
- `list()` - GET /v1/crisis-reviews (with query params)
- `get()` - GET /v1/crisis-reviews/:id
- `assign()` - POST /v1/crisis-reviews/:id/assign
- `transition()` - POST /v1/crisis-reviews/:id/transition
- `revealContact()` - POST /v1/crisis-reviews/:id/reveal-contact

### State Machine (enforced in UI + backend)

```
new → assigned → in_review → closed (terminal)
     ↑           ↑
     └───────────┘ (can reassign/unassign)
```

**Legal Transitions:**
- new → assigned (assign to reviewer)
- assigned → in_review (start review)
- assigned → new (unassign)
- in_review → closed (record outcome)
- in_review → assigned (reassign)
- closed → (none, terminal)

### Outcomes (required for closed state)

1. **no_action** - Reviewed, no immediate concern
2. **routine_follow_up_requested** - Follow-up suggested
3. **escalated_to_clinical_lead** - Escalated to lead for review

### Review Queue Features

**Table Columns:**
- State badge (color-coded: new=blue, assigned=yellow, in_review=purple, closed=gray)
- Owner (or "Unassigned")
- Flag count
- Last flag time (relative: "5m ago", "2h ago", "Nov 14")
- Age (since created: "15m", "3h", "2d")
- SLA status (ok=green, warning=yellow, breached=red)
- View button → detail page

**Filters:**
- State: all | new | assigned | in_review | closed
- Owner: all | me | unassigned
- Escalated to lead: checkbox

**Auto-Refresh:**
- Polls every 30 seconds
- Manual refresh button
- Shows last updated timestamp

**SLA Logic:**
- Default: 60 minutes (1 hour)
- Only applies to "new" (unassigned) items
- Warning at 80% (48 minutes)
- Breached at 100% (60 minutes)

### Review Detail Features

**Header:**
- Review ID (short: first 8 chars)
- State, flags count, created timestamp
- Owner (if assigned) + assigned timestamp
- Outcome (if closed) + closed timestamp
- Escalated to lead badge (if escalated)
- Revealed contact info (if revealed, shown in red box)

**Actions (state-dependent):**
- Assign to Me (only if new + unassigned)
- Start Review (assigned → in_review)
- Unassign (assigned → new)
- Close (in_review → closed, requires outcome + reason)
- Reveal Contact (any state, requires reason + confirmation)

**Flag Timeline:**
- Shows all de-identified flags for this review
- Grouped by signature, confidence, time bucket, model version
- Disclaimer: "No audio, transcript, or precise location data"

**State History:**
- Audit trail from crisis_review_events
- Shows: fromState → toState, timestamp, actor, reason
- Placeholder (requires backend endpoint for events)

### Reveal Contact Modal

**Guards:**
- Reason input (minimum 20 characters)
- Confirmation checkbox
- Submit button disabled until both valid

**Behavior:**
- Calls POST /v1/crisis-reviews/:id/reveal-contact
- Writes audit record (server-side)
- Returns: subjectId, emergencyContact, emergencyPhone
- Displayed in ReviewHeader (red box)
- NOT cached or stored (displayed once per page view)

**Example Reason:**
"Routine follow-up required based on repeated flag pattern over 24-hour window."

### Transition Modal

**For Closing (toState = 'closed'):**
- Outcome dropdown (required)
- Reason textarea (required, min 10 chars)
- Confirmation button

**For Other Transitions:**
- Reason textarea (optional)
- Confirmation button

### Safety Notice

**Displayed on:**
- Every queue page (top of list)
- Every detail page (top of page)

**Content:**
- "Advisory indicators for human review. Not a diagnosis."
- "This console does not contact the user or emergency services."
- Link: "See organization crisis procedure →"

## Architecture Notes

1. **No Automatic Actions**: No code path for sending messages, calls, or external triggers. Only manual human review workflow.

2. **Reveal Contact (Guarded)**: Requires reason (≥20 chars) + confirmation. Audit trail written server-side. Contact displayed once, not cached.

3. **State Machine (Client + Server)**: UI shows only legal transitions. Server validates (B3.1). Mismatch returns `REVIEW_TRANSITION_INVALID`.

4. **Auto-Refresh (30s)**: Queue polls backend every 30 seconds. Manual refresh button for immediate update.

5. **SLA Tracking**: Computed client-side from `createdAt` timestamp. Only applies to "new" (unassigned) items. Warning at 80%, breached at 100%.

6. **Flag Timeline (De-identified)**: Shows only allow-list fields (signature, confidence, time bucket, model version). No audio, transcript, features.

7. **Escalated to Lead**: Items with `escalatedToLead=true` visually distinct (red badge). Team lead filter available.

8. **Outcome Required**: Closing review requires outcome selection + reason (min 10 chars). Enforced client-side + server-side.

9. **Safety Notice (Always Visible)**: Shown on every page (queue + detail). Links to organization crisis procedure.

10. **Keyboard-Friendly**: All interactive elements accessible via keyboard (Tab, Enter, Space). Modal dialogs trap focus.
