## Workers Created

### 1. PopulationAggregationProcessor

**Queue:** `ajna.population.aggregate`

**Job Payload:**
```typescript
{
  granularity: 'week' | 'month',
  week_start?: string,  // YYYY-MM-DD (Monday)
  month_start?: string  // YYYY-MM-DD (first of month)
}
```

**Behavior:**
- Queries subjects with active `population_use` consent
- Aggregates by `community_id` + `age_band` + time period
- Computes: subjects_n, flag_count, PRI stats (mean/median/p10/p90), deviation_share
- Applies K-anonymity suppression: if `subjects_n < 10`, stores `suppressed=true` with NULL counts
- Writes to `community_week_agg` or `community_month_agg` tables
- Upserts for idempotency (ON CONFLICT DO UPDATE)

**Key Features:**
- **K-anonymity enforcement:** Small cells (<10 subjects) are suppressed at storage time
- **Consent filtering:** Only includes subjects with `population_use=true` and `revoked_at IS NULL`
- **NO subject_id storage:** Aggregates contain only counts and statistics
- **RLS context:** Uses `app_worker` role for write access

**Logging Example:**
```
Week aggregation complete: 143 groups, 89 released, 54 suppressed
```

### 2. CommunityVectorProcessor

**Queue:** `ajna.population.compute-vectors`

**Job Payload:**
```typescript
{
  community_id?: string  // If omitted, compute all communities
}
```

**Behavior:**
- Extracts 5 raw features from community aggregates:
  - `flag_rate` (flags per subject per month)
  - `mean_pri` (0-100)
  - `deviation_share` (0-1)
  - `deprivation_index` (0-1)
  - `population_density` (normalized)
- Normalizes features via z-score normalization (mean=0, SD=1)
- Computes 128-dim embedding via linear projection + sine/cosine rotation
- Stores in `community_vectors` table (pgvector format: `'[0.1, 0.2, ...]'`)
- Includes `features` JSONB for transparency

**Key Features:**
- **Dimensionality expansion:** 5 features → 128-dim embedding (from P0.3 findings)
- **Unit normalization:** Embeddings normalized to unit length for cosine similarity
- **Feature transparency:** Stores raw feature values alongside embedding
- **HNSW index support:** Embeddings formatted for pgvector HNSW index

**Embedding Algorithm:**
```typescript
// Simple linear projection + rotation
for (let i = 0; i < 128; i++) {
  const baseIdx = i % 5;  // Cycle through 5 features
  const phase = (i / 128) * 2 * π;
  embedding[i] = features[baseIdx] * cos(phase + baseIdx);
}
// Normalize to unit length
magnitude = sqrt(sum(embedding^2));
embedding = embedding / magnitude;
```

**Note:** This is a placeholder algorithm. Production implementation should use a trained model (e.g., autoencoder, metric learning).

**Logging Example:**
```
Vectors computed for 47 communities (128-dim embeddings)
```

### 3. CommunityClusterProcessor

**Queue:** `ajna.population.cluster`

**Job Payload:**
```typescript
{
  k?: number  // Number of clusters (default: 5)
}
```

**Behavior:**
- Loads all community vectors from `community_vectors` table
- Runs K-means++ clustering (smart centroid initialization)
- Iterates until convergence (max 100 iterations, threshold: 0.001)
- Labels clusters based on average feature patterns (descriptive, NOT diagnostic)
- Computes composite underserved score (0-100):
  - 40% weight: deprivation index
  - 30% weight: low PRI (inverse)
  - 20% weight: deviation share
  - 10% weight: flag rate
- Stores results in `community_clusters` table

**Key Features:**
- **K-means++ initialization:** Better convergence than random initialization
- **Convergence detection:** Stops when centroid movement < 0.001
- **Descriptive labels:** Avoids diagnostic language (no "diagnos*", "disease", "disorder")
- **Transparent scoring:** Stores `score_breakdown` JSONB with component weights
- **Empty cluster handling:** Reinitializes to random point if cluster becomes empty

**Label Examples:**
- "High deprivation, lower resilience scores, frequent deviations"
- "Low deprivation, higher resilience scores"
- "Typical community pattern"

**Logging Example:**
```
K-means converged in 23 iterations (max movement: <0.001)
Clustering complete: 5 clusters, 47 communities
```

## Privacy Guarantees

### K-Anonymity Enforcement

**Storage-level suppression:**
```typescript
const suppressed = subjects_n < LIMITS.POPULATION.MIN_K;  // K=10

await client.query(`
  INSERT INTO community_week_agg (subjects_n, flag_count, mean_pri, suppressed)
  VALUES ($1, $2, $3, $4)
`, [
  suppressed ? null : subjects_n,  // NULL if suppressed
  suppressed ? null : flag_count,
  suppressed ? null : meanPri,
  suppressed
]);
```

**Database constraint:**
```sql
CONSTRAINT suppressed_nulls_check CHECK (
  (suppressed = FALSE AND subjects_n >= 10) OR
  (suppressed = TRUE AND subjects_n IS NULL)
)
```

### Consent Filtering

Only subjects with active `population_use` consent contribute to aggregates:

```sql
WHERE c.population_use = TRUE
  AND c.revoked_at IS NULL
```

Revoking consent removes subject from **future** aggregates only. Past aggregates are unchanged (contain no subject_id).

### No Subject Identifiers

Aggregates store only:
- Counts (subjects_n, flag_count)
- Statistics (mean, median, percentiles)
- Group keys (community_id, age_band, date)

**NO storage of:**
- subject_id
- session_id
- Individual metric values

### Recommended Cron Schedule

```typescript
// apps/api/src/workers/scheduler.service.ts

// Daily: compute weekly aggregates for last week
await queue.add('ajna.population.aggregate', {
  granularity: 'week',
  week_start: getLastMonday(),

// Monthly: compute monthly aggregates
await queue.add('ajna.population.aggregate', {
  granularity: 'month',
  month_start: getFirstOfMonth(),
}, { cron: '0 3 1 * *' });  // 3am on 1st of month

// Weekly: recompute community vectors
await queue.add('ajna.population.compute-vectors', {}, 
  { cron: '0 4 * * 0' });  // 4am every Sunday

// Weekly: recompute clusters
await queue.add('ajna.population.cluster', { k: 5 },
  { cron: '0 5 * * 0' });  // 5am every Sunday
```

- **Consent revocation** - No immediate action (next scheduled run excludes subject)

## Performance Characteristics

### PopulationAggregationProcessor

**Query Complexity:** O(S × D) where S = subjects, D = days in period

**Expected Runtime:**
- 1k subjects, 7-day period: ~100ms
- 10k subjects, 7-day period: ~500ms
- 100k subjects, 30-day period: ~2-3s

**Bottlenecks:**
- JOIN across subjects + deviation_flags + pri_daily
- ARRAY_AGG for PRI values (can be large)

**Optimizations:**
- Composite index: `(community_id, age_band, date)`
- Partial index on consented subjects only

---

### CommunityVectorProcessor

**Computation Complexity:** O(C × F) where C = communities, F = feature dimension (5)

**Expected Runtime:**
- 50 communities: ~200ms (single community), ~1s (all)
- 500 communities: ~500ms (single), ~5s (all)

**Bottlenecks:**
- Z-score normalization requires 2 passes (mean, then SD)
- 128-dim embedding projection

**Optimizations:**
- Batch normalization (compute stats once for all communities)
- Parallel processing (consider worker pool for 1000+ communities)

---

### CommunityClusterProcessor

**Clustering Complexity:** O(K × C × D × I) where K = clusters, C = communities, D = dimensions (128), I = iterations

**Expected Runtime:**
- 50 communities, K=5: ~500ms (20-30 iterations typical)
- 500 communities, K=10: ~3-5s (30-40 iterations)

**Convergence:**
- K-means++ typically converges in 20-40 iterations
- Max iterations: 100 (safety limit)
- Convergence threshold: 0.001 (centroid movement)

**Bottlenecks:**
- Euclidean distance computation (128-dim vectors)
- Centroid recomputation (requires summing all cluster members)

**Optimizations:**
- Early stopping (convergence check)
- Empty cluster reinitialization (prevents division by zero)

## Known Limitations

### 1. Placeholder Embedding Algorithm

**Current:** Linear projection + sine/cosine rotation (no training)

**Production:** Should use trained model (e.g., autoencoder, contrastive learning)

**Impact:** Similarity search may have lower precision (<90%) compared to trained embeddings (>95%)

**Mitigation:** P0.3 findings show HNSW achieves >95% recall even with random embeddings at small scale. For production (100k+ communities), train a model.

---

### 2. Complementary Suppression Not Implemented

**Spec Requirement:** "Complementary suppression to prevent subtracting totals to recover a small cell"

**Current:** Only primary K-anonymity suppression (cells with <10 subjects)

**Missing:** If `total=15` and `group_A=13`, then `group_B=2` (inferable, should suppress total)

**Impact:** Sophisticated users could recover small cells via arithmetic

**Mitigation:** Add complementary suppression logic in a follow-up task (B5.1 hardening phase)

---

### 3. Fixed K Value

**Current:** K=10 (hard-coded in LIMITS.ts)

**Spec Note:** "K from config (default 10)"

**Missing:** Runtime configuration (env var or database setting)

**Impact:** Cannot adjust K without code change

**Mitigation:** Low priority (K=10 is industry standard for health data)
