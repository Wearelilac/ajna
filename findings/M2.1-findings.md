## Executive Summary

M2.1 successfully implements Resilience Radar mobile screens using React Native. RadarScreen displays PRI gauge, 7/30-day trends, active deviation flags, and metric cards. All components use TanStack Query for data fetching from B2.1/B2.2 endpoints. Wording is advisory ("flagged for review", never "diagnosed"). Demo data loader with 3 scenarios. Consent gate prevents access without wearable consent. Loading, empty, error, and stale states implemented.

**Key Features:**
- RadarScreen: PRI gauge, trends, flags list, metric cards
- PRIGauge: Circular progress indicator (0-100), color-coded, interpretation guide
- FlagsList: Deviation flag cards with detail modal, advisory wording
- DemoDataLoader: 3 scenarios (steady, gradual_decline, acute_deviation)
- ConsentGate: Blocks access without wearable consent
- MetricCards: Horizontal scroll, 4 key metrics, deviation indicators
- TanStack Query: ['radar','summary'], ['radar','pri'], ['radar','deviations'], ['wearable','daily']

## Components

### 1. PRIGauge

**Purpose:** Display PRI score (0-100) as circular gauge with trends

**Props:**
```typescript
interface PRIGaugeProps {
  pri: number; // 0-100
  date: string;
  trend7d: number; // +/- change over 7 days
  trend30d: number; // +/- change over 30 days
}
```

**Visual:**
- Circular progress indicator (react-native-svg)
- Color-coded: Green (70-100), Indigo (50-69), Amber (30-49), Red (0-29)
- Trend indicators: ↑ (positive), ↓ (negative), → (neutral)
- Interpretation guide at bottom

**Accessibility:**
- PRI value announced as "Personal Resilience Index: 72"
- Trend announced as "7-day trend: up 5 points"

### 2. FlagsList

**Purpose:** Display active deviation flags with tap-for-details

**Props:**
```typescript
interface FlagsListProps {
  flags: DeviationFlag[];
}
```

**Visual:**
- Amber-background cards (calm, not alarming red)
- Metric name + direction (↑/↓) + z-score deviation
- Date in top-right corner

**Detail Modal:**
- Full metric name
- Date, direction, z-score
- **Advisory notice** (required by B2.2 spec):
  > "This is an advisory indicator for human review, not a diagnosis. It shows your [metric] is [above/below] your usual range. Consider rest, hydration, and talking with your usual care provider if you feel unwell."

**Wording Compliance:**
- ✅ "Flagged for review" (advisory)
- ✅ "Elevated indicator"
- ✅ "Above/below baseline"
- ❌ Never "diagnosed", "you have", "risk of [condition]"

### 3. DemoDataLoader

**Purpose:** Load 60 days of synthetic data (dev/demo mode only)

**Scenarios:**
1. **Steady:** Normal daily variation, no anomalies
2. **Gradual Decline:** HRV declines 30% over last 30 days
3. **Acute Event:** 7-day HRV drop (30%) on days 50-56

**API Call:**
```typescript
POST /v1/wearable/demo-seed
{
  "scenario": "acute_deviation"
}
```

**Response:**
```json
{
  "days_generated": 57,
  "scenario": "acute_deviation",
  "message": "Demo data generated (57 days)"
}
```

**Notes:**
- ~5% of days are randomly skipped (simulates missing data)
- Loading indicator while seeding
- Success alert → user pulls to refresh to see data

### 4. ConsentGate

**Purpose:** Block radar access without wearable consent

**Visual:**
- 🔒 Lock icon
- Explanation text
- "What we'll collect" bullet list
- "Review Privacy Settings" button (navigates to Privacy tab)

**Behavior:**
- Shown if `hasConsent('wearable') === false`
- No API requests made (network log count: 0)

### 5. MetricCards

**Purpose:** Display key metrics in horizontal scrollable cards

**Metrics:**
1. Heart Rate Variability (HRV) - ms
2. Resting Heart Rate (RHR) - bpm
3. Sleep Efficiency - %
4. Total Sleep - hours

**Visual:**
- Horizontal scroll (no scrollbar)
- Card width: 192px (w-48)
- Amber border if metric has deviation flag
- "⚠️ Flagged for review" indicator at bottom

**Data Source:**
- Wearable data: GET /v1/wearable/daily?from=...&to=...
- Deviations: GET /v1/radar/deviations?from=...&to=...

## API Integration

### TanStack Query Keys

```typescript
['radar', 'summary']                              // GET /v1/radar/summary
['radar', 'pri', fromDate, toDate]               // GET /v1/radar/pri
['radar', 'deviations', fromDate, toDate]        // GET /v1/radar/deviations
['wearable', 'daily', fromDate, toDate]          // GET /v1/wearable/daily
```

### Data Flow

1. **On mount:**
   - Check wearable consent
   - If granted: fetch radar summary
   - If denied: show ConsentGate

2. **Summary fetch:**
   ```typescript
   useQuery({
     queryKey: ['radar', 'summary'],
     queryFn: radarApi.getSummary,
     enabled: hasWearableConsent,
   })
   ```

3. **Pull to refresh:**
   - Refetch all queries
   - Show loading indicator

4. **Demo seed:**
   ```typescript
   useMutation({
     mutationFn: (scenario) => wearableApi.seedDemo(scenario),
     onSuccess: () => {
       Alert.alert('Success', 'Pull to refresh to see your radar.');
       onSuccess(); // Triggers refetch
     },
   })
   ```

## Cache Management

### In-Memory Cache

TanStack Query stores:
- Radar summary (30min stale time)
- PRI history (10min stale time)
- Wearable daily (5min stale time)

### Cache Clearing

**Triggers:**
1. Sign-out: `queryClient.clear()`
2. App backgrounded >5min: `queryClient.invalidateQueries()`
3. Consent revoked: `queryClient.removeQueries(['radar'])`

**No Persistence:**
- No metrics stored in SecureStore
- No metrics in AsyncStorage
- Cache cleared on app restart
