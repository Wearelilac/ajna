## Experiments & Results

### 1. Environment Validation

**Goal:** Refuse to boot on missing or malformed env vars, print names only (no values).

**Deliverable:** `common/config.ts` (Zod schema)

**Implementation:**
- Validates 6 required vars: `AJNA_ENV`, `AJNA_KEK_BASE64`, `AJNA_JWT_SECRET`, `DATABASE_URL`, `REDIS_URL`, `AJNA_SCORING_*`
- On error: prints variable names only, values redacted
- Exit code: 1 on validation failure

**Test Results:**
- ✓ Missing `AJNA_KEK_BASE64` triggers error message with only variable name
- ✓ Invalid `DATABASE_URL` (not a URL) triggers validation error
- ✓ Valid config passes and returns typed object

**Behavior (from spec):** `common/config.ts`
```typescript
export function validateConfig(): AppConfig {
  try {
    return envSchema.parse(process.env);
  } catch (err) {
    if (err instanceof z.ZodError) {
      const missing = err.errors.map((e) => e.path.join('.')).join(', ');
      console.error(`Missing or invalid environment variables: ${missing}`);
      process.exit(1);
    }
    throw err;
  }
}
```

### 2. Standard Error Shape

**Goal:** Every error path returns `{ statusCode, error, code, message, requestId }` (00-stack-and-conventions.md, section 4).

**Deliverable:** `common/exception-filter.ts` + `common/errors.ts`

**Error Codes Registry** (stable, UPPER_SNAKE):
```
INTERNAL_SERVER_ERROR
NOT_FOUND
RATE_LIMIT_EXCEEDED
VALIDATION_FAILED
INVALID_REQUEST_ID
WEARABLE_PAYLOAD_INVALID (for B2.1)
FLAG_FIELD_NOT_ALLOWED (for B3.1)
UNAUTHORIZED, FORBIDDEN, CONSENT_REQUIRED (for B1.3)
DATABASE_ERROR
SERVICE_UNAVAILABLE
```

**Test Results:**
- ✓ 404 error: returns correct shape with code `NOT_FOUND`
- ✓ 422 validation error: returns code `VALIDATION_FAILED`
- ✓ All responses include valid UUID `requestId`
- ✓ `statusCode` matches HTTP status
- ✓ `error` field is standard HTTP reason phrase

**Example:**
```json
{
  "statusCode": 404,
  "error": "Not Found",
  "code": "NOT_FOUND",
  "message": "Endpoint not found",
  "requestId": "12345678-1234-5678-1234-567812345678"
}
```

### 3. Request ID Generation & Roundtrip

**Goal:** Accept valid `x-request-id` or generate UUID; attach to logs and response headers (00-stack-and-conventions.md, section 3).

**Deliverable:** `common/request-id.middleware.ts`

**Implementation:**
- Reads `x-request-id` from request headers
- Validates UUID format (v4 regex)
- If invalid or missing: generates new UUID
- Attaches to `req.id` for logging
- Returns in response header `x-request-id`

**Test Results:**
- ✓ Valid UUID: accepted and echoed in response
- ✓ Invalid UUID: rejected, new one generated
- ✓ Missing ID: generates new one
- ✓ All generated IDs are valid v4 UUIDs

### 4. Structured Logging with Redaction

**Goal:** JSON logs (pino) with automatic redaction of PHI, audio data, tokens (00-stack-and-conventions.md, section 5).

**Deliverable:** `common/logger.ts`

**Redaction Rules:**
```typescript
redact: {
  paths: [
    // Authentication
    '*.authorization', '*.token', '*.jwt', '*.password', '*.secret', '*.key',
    
    // Personal info
    '*.email', '*.phone', '*.ssn', '*.name',
    
    // Health data (PHI)
    '*.hrv_rmssd_ms', '*.resting_hr_bpm', '*.skin_temp_dev_c', '*.metric_*',
    
    // Audio (class 1)
    '*.audio', '*.audio_samples', '*.waveform', '*.spectrogram', '*.embedding',
    
    // Encryption
    '*.kek', '*.dek', '*.ciphertext',
    
    // Full bodies
    'req.body', 'reqBody',
  ],
  remove: true,
}
```

**Test Results:**
- ✓ Authorization header redacted
- ✓ Email addresses redacted
- ✓ Audio samples not logged
- ✓ Wearable metrics redacted
- ✓ Non-sensitive fields preserved (event, timestamp, action)

### 5. Rate Limiting

**Goal:** Protect endpoints from abuse; default 60 req/min, overridable per-route.

**Implementation:**
- Fastify `rate-limit` plugin
- Default: 60 requests per minute per IP
- Error: 429 RATE_LIMIT_EXCEEDED
- Decorator support for per-route overrides (added in B2.1+)

**Test Results:**
- ✓ Plugin configured in app bootstrap
- ✓ Error shape correct (429 status, `RATE_LIMIT_EXCEEDED` code)

### 6. Health Endpoints

**Goal:** Liveness (`/v1/health`) and readiness (`/v1/ready`) probes.

**Deliverables:**
- `GET /v1/health`: Returns `{ status: "healthy", checks: { database: "ok", redis: "ok" } }`
- `GET /v1/ready`: Checks connectivity, returns degraded flags if DB/Redis unavailable

**Test Results:**
- ✓ `/v1/health` returns 200 instantly
- ✓ `/v1/ready` returns 200 with ready status
- ✓ Both return valid request IDs
- ✓ Response headers include `x-request-id`

**Latency (local):**
