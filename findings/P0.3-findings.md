## Schema Design

### Tables Created

1. **population_flags** (de-identified, row-level, 30-day retention)
   - Demographics: age_band, region_code, community_id, deprivation_index
   - Acoustic: signature, confidence, embedding (512-dim vector)
   - Temporal: time_bucket (hourly granularity, no precise timestamp)
   - **NO PHI**: subject_id NOT stored (uses session_id instead)

2. **community_pri_monthly** (aggregated, K≥10 enforced)
   - Metrics: avg_pri, p50_pri, p90_pri, high_risk_pct
   - Constraint: `CHECK (member_count >= 10)`

3. **care_gaps** (population-level, K≥10 enforced)
   - Gap types: 'frequent_flags', 'sustained_low_pri', 'sudden_decline'
   - Constraint: `CHECK (estimated_size >= 10)`

### Indexes

- **HNSW:** `idx_population_flags_hnsw` (vector_cosine_ops, m=16, ef_construction=64)
- **Composite:** time_bucket, region+age_band, community, signature

### RLS Policies

- app_official: **DENY** population_flags, **ALLOW** aggregates
- app_worker: **INSERT** population_flags only

## Risks & Mitigations

### Risk 1: High Suppression Rate

**Risk:** Small-cell suppression may hide too much data (30-40% of groups suppressed).

**Mitigation:** 
- Use coarser groupings (e.g., collapse age bands: '0-18', '19-50', '51+')
- Aggregate over longer time windows (monthly instead of weekly)
- Document suppression rates in dashboards ("X% of data suppressed for privacy")

**Status:** Acceptable for v1. Monitor in production.

### Risk 2: pgvector Memory Usage

**Risk:** HNSW indexes require ~2GB RAM for 100k vectors (512-dim).

**Mitigation:**
- Start with HNSW for accuracy
- If memory constrained, switch to IVFFlat (500MB, 90-95% recall)
- Implement rolling 30-day retention (auto-deletes old embeddings)

**Status:** Acceptable. Render.com PostgreSQL plans support 4GB+ RAM.

### Risk 3: RLS Performance Overhead

**Risk:** RLS policies add 5-10% query overhead.

**Mitigation:**
- Use composite indexes (region+age_band) to accelerate filtered queries
- Cache aggregated views (community_pri_monthly is computed monthly, not per-request)
- Benchmark on Render.com instance before launch

**Status:** Acceptable. RLS overhead is minor compared to security benefit.
