## API Endpoints Created

### Care Pathways

**GET /v1/care-pathways**
- **Access:** reviewer, clinical_supervisor, admin
- **Returns:** List of approved pathways
- **Fields:** id, title, eligibility, description, wordingSnippets, ownerRole, approvedBy, approvedOn, active

---

### Care Gaps

**GET /v1/care-gaps**
- **Access:** reviewer, clinical_supervisor, admin
- **Params:** gapType, status, limit, offset
- **Returns:** List of care gaps
- **Fields:** id, subjectId, gapType, dueDate, indicatorSummary, status, createdAt

**GET /v1/care-gaps/:id**
- **Access:** reviewer, clinical_supervisor, admin
- **Returns:** Single care gap detail
- **Error:** 404 if not found (REVIEW_NOT_FOUND)

**GET /v1/care-gaps/:id/matches**
- **Access:** reviewer, clinical_supervisor, admin
- **Returns:** Top-k pathway matches (ranked by similarity)
- **Fields:** id, pathwayId, rank, similarity, filteredBy, pathwayTitle, pathwayDescription

---

### Outreach Drafts

**GET /v1/outreach-drafts**
- **Access:** reviewer, clinical_supervisor, admin
- **Params:** status, limit, offset
- **Returns:** List of outreach drafts
- **Fields:** id, careGapId, pathwayId, body, language, readingLevel, status, generatedBy, createdAt, updatedAt

**GET /v1/outreach-drafts/:id**
- **Access:** reviewer, clinical_supervisor, admin
- **Returns:** Single draft detail
- **Error:** 404 if not found (REVIEW_NOT_FOUND)

**PUT /v1/outreach-drafts/:id/body**
- **Access:** reviewer, clinical_supervisor, admin
- **Body:** `{ body: string }`
- **Behavior:** Updates draft body, validates banned wording
- **Error:** 400 if banned wording detected (FLAG_FIELD_NOT_ALLOWED)

**POST /v1/outreach-drafts/:id/transition**
- **Access:** reviewer, clinical_supervisor, admin
- **Body:** `{ toStatus: string, reason?: string, editedBody?: string }`
- **Behavior:** Transitions draft status, records audit review
- **Error:** 400 if invalid transition (REVIEW_TRANSITION_INVALID)

## State Machine

### States

```
draft → in_review → approved | edited_approved | rejected → closed
```

- **draft:** Initial state (generated by worker)
- **in_review:** Reviewer has started review
- **approved:** Reviewer approved without edits
- **edited_approved:** Reviewer approved with editorial changes
- **rejected:** Reviewer rejected (with reason)
- **closed:** Terminal state (no further transitions)

### Valid Transitions

| From State | To States | Role Required |
|------------|-----------|---------------|
| draft | in_review | any |
| in_review | approved | reviewer, clinical_supervisor |
| in_review | edited_approved | reviewer, clinical_supervisor |
| in_review | rejected | reviewer, clinical_supervisor |
| approved | closed | any |
| edited_approved | closed | any |
| rejected | closed | any |
| rejected | in_review | any (re-review after edits) |
| closed | (none) | Terminal state |

### Invalid Transitions (Blocked)

- draft → approved (must go through in_review first)
- draft → rejected
- draft → closed
- in_review → closed (must approve/reject first)
- approved → in_review (can't un-approve)
- closed → * (terminal state)
- in_review → approved with role='staff' (only reviewer/clinical_supervisor can approve)

## Banned-Wording Lint

### Prohibited Terms (20 total)

**Diagnostic Language:**
- diagnosed, diagnosis, disorder, disease, condition

**Detection Language:**
- detected, flagged, identified, abnormal, alert

**Technical Language:**
- risk score, distress signature, acoustic pattern, voice analysis
- AI detected, algorithm found, system identified, automated screening
- audio analysis, vocal biomarker

### Enforcement

1. **Pre-save validation:** All draft body updates are linted before storage
2. **Transition validation:** edited_approved transitions validate edited_body
3. **Error response:** 400 with list of violations if banned wording found

**Example Error:**
```json
{
  "statusCode": 400,
  "errorCode": "FLAG_FIELD_NOT_ALLOWED",
  "message": "Draft contains banned wording: diagnosed, AI detected"
}
```

## Audit Chain

### Table: draft_reviews

**Fields:**
- id (UUID)
- draft_id (UUID FK)
- reviewer_id (UUID)
- reviewer_role (TEXT)
- from_status (TEXT)
- to_status (TEXT)
- reason (TEXT, optional)
- edited_body (TEXT, optional)
- prev_hash (TEXT, NULL for now - hash chain placeholder)
- row_hash (TEXT, generated)
- at (TIMESTAMPTZ)

**Behavior:**
- Every status transition inserts a review row
- Hash chain pattern (prev_hash → row_hash) for immutability detection
- No DELETE allowed (append-only log)

**Example Audit Chain:**
```
1. draft → in_review (reviewer: alice, reason: "Starting review", at: 2026-11-14T10:00:00Z)
2. in_review → edited_approved (reviewer: alice, reason: "Minor wording fixes", edited_body: "...", at: 2026-11-14T10:15:00Z)
3. edited_approved → closed (reviewer: bob, reason: "Archived after 30 days", at: 2026-12-14T10:00:00Z)
```

## Privacy Guarantees

### 1. No Automatic Sending

**Code-Level Guarantee:**
- No messaging library imports (twilio, sendgrid, mailgun, etc.)
- Approval status does NOT trigger delivery
- "approved" is a reviewer decision ONLY

**Static Verification:**
```bash
grep -r "twilio\|sendgrid\|mailgun\|ses\|sns\|smtp\|email\|sms" apps/api/src/caregap/
# Expected: 0 results
```

### 2. Consent Filtering

**Worker Behavior (Future):**
- Care-gap detection only includes subjects with `population_use=true` consent
- Revoking consent closes open drafts with reason `consent_withdrawn`

**Query Pattern:**
```sql
FROM subjects s
INNER JOIN consents c ON s.subject_id = c.subject_id
WHERE c.population_use = TRUE
  AND c.revoked_at IS NULL
```

### 3. Indicator Summary (No PHI)

**What's Included:**
- Age band (coarse: '0-18', '19-50', '51+')
- Gap type ('overdue_screening', 'frequent_flags', etc.)
- Days overdue (integer)
- Flag count (integer)
- Screening type ('well_child_18m', 'adult_comprehensive', etc.)

**What's Excluded:**
- Audio data, transcripts, features
- Exact timestamps (only date granularity)
- Location data
- Raw metric values
- Subject name, contact info

## Template-Only Draft Generation

### Approach (from P0.4 Findings)

**v1:** Template-only (NO LLM)
- Uses approved wording_snippets from care_pathways table
- Substitutes age_band, screening_type, days_overdue
- Fast (<1ms), free ($0), 100% compliant

**Example Template:**
```
"Hello! We would like to offer you a [screening_type] screening. 
This screening is recommended for [age_band] and is currently 
[days_overdue] days overdue. Please contact us to schedule."
```

**Impact:** GET /v1/care-gaps/:id/matches will return empty list

**Mitigation:** Add worker in follow-up task (requires sentence-transformer embeddings)

---

### 3. No Draft Generation Worker Yet

**Current:** Endpoints ready, but no worker to populate outreach_drafts table

**Missing:** `ajna.caregap.draft` worker (template-only generation)

**Impact:** Endpoints will return empty lists until worker is implemented

**Mitigation:** Add worker in follow-up task (simple template substitution)

---

### 4. Hash Chain Not Fully Implemented

**Current:** `prev_hash` and `row_hash` fields exist, but hash computation is placeholder (uses gen_random_uuid())

**Missing:** `compute_review_hash()` function (SHA-256 of prev_hash + row_data)

**Impact:** Cannot detect audit chain tampering

**Mitigation:** Implement in B5.1 (hardening phase)

---

### 5. No Complementary Suppression

**Current:** Only primary K-anonymity suppression (cells with <10 subjects)

**Missing:** Complementary suppression (if total=15 and group_A=13, suppress total to prevent inferring group_B=2)

**Impact:** Sophisticated users could recover small cells via arithmetic

**Mitigation:** Add in B5.1 (hardening phase)
