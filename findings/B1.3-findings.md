## Components Delivered

### 1. Authentication Service ✅
- **Register:** Email + password (12 char min, complexity required)
- **Login:** Constant-time password comparison, generic error (no email enumeration)
- **Refresh:** Token rotation prevents reuse (family revocation on reuse)
- **Logout:** Revoke refresh tokens
- **Hashing:** Scrypt with random salt (production: use bcrypt/argon2)
- **JWT:** 15 min access, 30 day refresh, `AJNA_JWT_SECRET` from env

### 2. Consent Service ✅
- **Scopes:** `wearable`, `monitor_me`, `population_use`
- **Operations:** Grant (with textVersion), revoke, get all, get one, check active
- **Append-only:** Each action inserts new row (tracks full history)
- **Revocation:** Takes effect immediately (ConsentGuard checks at request)
- **Versioning:** Requires current `textVersion` to grant (prevents outdated consent)

### 3. Audit Service ✅
- **Append-only:** Never edited, only inserted
- **Hash-chained:** `hash = SHA-256(prev_hash || canonical_row)`
- **Verify:** `verifyChain()` detects tampering in any row
- **Query:** By subject, by action, recent entries (admin only)
- **Immutable:** No UPDATE or DELETE grants to any role

### 4. Guards & Decorators ✅
- **AuthGuard:** Validates JWT, extracts `subject_id` and `role`
- **RolesGuard:** Enforces role requirements via metadata
- **@RequiresConsent:** Decorator for consent-gated routes
- **ConsentGuard:** Checks active consent at request time

### 5. DTOs ✅
- Register, login, refresh, logout request/response schemas
- Consent grant/revoke request/response schemas
- All validated with Zod

## Implementation Highlights

### Refresh Token Rotation Pattern
```
Client has token T1
  ↓
POST /v1/auth/refresh with T1
  ↓
Server checks: Is T1 valid? Is T1 already replaced? Is T1 revoked?
  ↓
If reused (already replaced) → Revoke entire family, return 401
  ↓
If valid → Issue new T2, mark T1 as replaced_by T2, return T2
  ↓
Client stores T2
```

### Consent Flow
```
User grants consent for 'wearable' scope
  ↓
POST /v1/consents/wearable with { granted: true, textVersion: "1.0" }
  ↓
Consent service verifies textVersion is current
  ↓
Inserts new consents row (granted = true)
  ↓
ConsentGuard on next protected request checks: Is wearable granted?
  ↓
Immediately after revoke → ConsentGuard denies until re-granted
```

### Audit Chain Verification
```
Every row: hash = SHA-256(previous_hash || canonical_row)
  ↓
verifyChain() recomputes all hashes from start
  ↓
If any hash mismatch → Row tampered, report seq number
  ↓
Test: Alter one byte of ciphertext → Detection confirmed
```

## Remaining B1.3 Tasks (Quick)

### Database Migrations
```sql
-- Add auth_accounts table
CREATE TABLE auth_accounts (
  subject_id UUID PRIMARY KEY REFERENCES subjects,
  email_hash BYTEA UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role TEXT,
  created_at TIMESTAMPTZ,
  disabled_at TIMESTAMPTZ
);

-- Add refresh_tokens table
CREATE TABLE refresh_tokens (
  id UUID PRIMARY KEY,
  subject_id UUID NOT NULL,
  token_hash BYTEA UNIQUE NOT NULL,
  expires_at TIMESTAMPTZ,
  revoked_at TIMESTAMPTZ,
  replaced_by UUID REFERENCES refresh_tokens(id)
);

-- Add consent_texts table
CREATE TABLE consent_texts (
  scope TEXT,
  version TEXT,
  body TEXT,
  published_at TIMESTAMPTZ,
  PRIMARY KEY (scope, version)
);

-- Add consents table (append-only)
CREATE TABLE consents (
  id UUID PRIMARY KEY,
  subject_id UUID NOT NULL REFERENCES subjects,
  scope TEXT NOT NULL,
  granted BOOLEAN NOT NULL,
  text_version TEXT,
  at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ NOT NULL
);

-- Add audit_log table (append-only, hash-chained)
CREATE TABLE audit_log (
  seq BIGSERIAL PRIMARY KEY,
  at TIMESTAMPTZ NOT NULL,
  actor_subject_id UUID,
  actor_role TEXT NOT NULL,
  action TEXT NOT NULL,
  target_type TEXT,
  target_id UUID,
  detail JSONB,
  subject_id UUID,
  prev_hash TEXT,
  hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL
);
```
