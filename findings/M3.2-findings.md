## Implementation

### Architecture

**Components (`apps/mobile/src/features/monitor/`):**
1. **MonitorScreen** - Main screen (explainer, start/stop, summary)
2. **ListeningIndicator** - Visible banner during session (elapsed/remaining time, flags sent)
3. **PostSessionSummary** - Post-session stats (duration, flags sent)
4. **CrisisPanel** - Static helpline info (988, always visible)

**Hooks:**
1. **useMonitorSession** - Server session lifecycle (start, end, get active)
2. **useFlagSender** - Network bridge (queue flags, send to API, retry on failure)

**API Client (`apps/mobile/src/api/monitor.ts`):**
- `startSession()` - POST /v1/monitor/sessions
- `endSession()` - POST /v1/monitor/sessions/:id/end
- `getActiveSession()` - GET /v1/monitor/sessions/active
- `sendFlag()` - POST /v1/monitor/flags

### Data Flow

```
EdgeController.onFlag → useFlagSender (queue) → monitorApi.sendFlag → B3.1 endpoint
                                ↓
                          In-memory queue (max 20)
                                ↓
                      Retry every 5s on failure
```

### Privacy Guarantees

**1. Flag Sender (Single Network Bridge)**
- Only `useFlagSender.ts` imports network code
- Queues flags in memory (max 20, never persisted)
- Queue cleared on session end or sign-out
- No audio, features, or derived data in queue

**2. Offline Handling**
- Flags queued if network unavailable
- Retry every 5 seconds
- Drop oldest if queue > 20 flags
- Queue cleared on session end (no permanent storage)

**3. Wording (Advisory Only)**
- "Signals flagged for review" (not "diagnosed")
- "Nothing recorded or saved" (explicit guarantee)
- Crisis panel: "Ajna does not contact emergency services or anyone on your behalf"
- No promises of intervention

### Session Lifecycle

**Start Flow:**
1. User taps "Start Monitoring"
2. Confirm dialog: "No audio recorded or saved"
3. Request mic permission
4. Call `startSession()` → B3.1 returns sessionId + maxDurationSec
5. Build thresholds from P0.2 limits
6. Start EdgeController with callbacks:
   - `onFlag`: Send to useFlagSender
   - `onIndicator`: Show/hide indicator
7. Show ListeningIndicator banner

**Stop Flow:**
1. User taps "Stop Monitoring" OR timeout reached OR app backgrounded
2. Stop EdgeController (zero-fills buffer)
3. Get final status (flagsEmitted, elapsedMs)
4. Call `endSession()` → B3.1 closes session
5. Show PostSessionSummary (duration, flags sent)

**Interruption Handling:**
- Background: `EdgeController.onBackground()` → stop('background')
- Consent revoked: `EdgeController.onConsentRevoked()` → stop('consent_revoked')
- Timeout: Auto-stop at maxDurationSec
- Error: Catch in inference loop → stop('error')

### useFlagSender Hook

**Features:**
- In-memory queue (max 20 flags)
- Send immediately on flag emission
- Retry every 5 seconds on failure
- Drop oldest if queue full
- Clear on session end or sign-out

**State:**
- `queueLength`: Number of pending flags
- `isSending`: Boolean flag for send in progress

**Methods:**

## Architecture Notes

1. **Single Network Bridge**: Only `useFlagSender.ts` bridges edge and network. All other files are UI or state management.

2. **In-Memory Queue**: Flags stored in `useRef` (not React state, not AsyncStorage). Cleared on session end.

3. **Retry Logic**: 5-second interval retries sending queued flags. Stops when queue empty.

4. **Drop Oldest**: If queue > 20 flags, drop oldest to prevent memory growth.

5. **Indicator Before Audio**: `onIndicator(true)` called before `audioSource.start()` ensures visible state.

6. **Auto-Stop Timer**: `setTimeout()` in EdgeController ensures server-enforced maxDurationSec respected.

7. **Crisis Panel (Static)**: Always visible, not triggered by flags. No automatic outbound contact.

8. **Wording (Advisory)**: All text emphasizes advisory nature, no diagnosis, no automatic actions.

9. **Post-Session Summary**: Shows only counters (duration, flags sent), never flag contents.

10. **Error Handling**: API errors shown in UI, do not crash app or lose session state.
