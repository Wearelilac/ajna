# W5.1-demo-seed-and-end-to-end

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `W1.1`, `W3.1`, `W4.1`, `W4.2`, `B5.1`, `M5.1`, and all `findings/P0.*` notes.

## Purpose

Make the whole of Ajna demoable and verifiable: a reproducible demo dataset, an end-to-end test across mobile, API and dashboard, a rehearsed demo script, and a final coverage check against the master plan.

## What already exists

- Foundation files, P0 findings.
- Backend complete and hardened (`B1.x` to `B5.1`), mobile complete and proven (`M1.x` to `M5.1`), dashboard pages for review, population and care gaps (`W1.1`, `W3.1`, `W4.1`, `W4.2`).
- Demo endpoints: `POST /v1/wearable/demo-seed`, `POST /v1/admin/demo/population-seed`.

## Scope

1. **Demo dataset command:** one script (`npm run demo:reset`) that resets a demo environment and seeds: staff accounts (Reviewer, Official, Admin), a demo end user, a synthetic population with communities and clusters, care history with overdue gaps, pathways, and a few pre-made crisis review items created through the real flag ingest path (not direct inserts). Deterministic with a seed.
2. **End-to-end tests (Playwright for web, plus a mobile smoke run or scripted API driver for the phone steps):**
   - A: demo user loads `acute_deviation` data, sees a deviation flag and PRI drop on Radar.
   - B: monitor session (with the audio fixture or an injected flag) produces a de-identified flag; the Reviewer sees it in the crisis review queue; assigns, reviews, closes with outcome.
   - C: Official views the population dashboard and a suppressed cell; Reviewer processes a care gap draft through approve/edit/reject.
   - Privacy: proof screen counters and proxy capture agree; reveal-contact requires a reason and appears in the audit report.
3. **Demo script** (`docs/demo-script.md`): a 5-7 minute walkthrough in the order privacy claim → Radar → Monitor Me → crisis review → population dashboard → care-gap draft, with speaker notes, expected screens, and fallback steps if a service is slow.
4. **Final coverage check:** a table in `docs/coverage-check.md` mapping every requirement in the master plan's coverage table to files built and the acceptance evidence (test names, numbers), with any unmet item stated plainly.
5. **Dashboard polish:** consistent empty/loading/error states, responsive pass, accessibility pass, footer and wording consistency across all web pages.
6. **README and runbook:** how to run locally, how to deploy to Render/Upstash, environment variables, how to run the proof suite, known limitations from all `Gaps found`.
7. **Smoke monitor:** a script/CI job that hits health and ready endpoints and a minimal read path after each deploy.

## Out of scope

- New features, new endpoints.
- Marketing material.
- Production launch activities.

## Contracts used

Reads `contracts/openapi.v1.yaml` and `contracts/scoring.internal.v1.yaml`. Publishes nothing.

## Data model

None new. Demo data lives in existing tables with a `demo` marker in the seed script's own records (for example, synthetic email domain `@demo.ajna.invalid`); the reset command deletes only those.

## Rules and behaviour

- Demo data is synthetic only. No real people, no real health data, no real audio.
- The demo flag path goes through the real API validation and allow-list; no shortcuts that bypass privacy checks.
- Demo mode flags must be off in production configuration, verified by a test.
- Wording and no-automatic-action rules still apply to demo content and scripts.
- Anything that fails in rehearsal is documented honestly in `docs/coverage-check.md`, not hidden.

## Acceptance checks

- [ ] `demo:reset` completes in a reported time and is deterministic (two runs produce identical checksums of seeded data).
- [ ] Playwright suite: all scenarios pass; report scenario count, duration and flaky-test count (0 expected).
- [ ] Scenario B verified through the real flag endpoint with only allow-listed fields (show the captured request).
- [ ] Privacy scenario: proxy capture and proof-screen counters agree; reveal-contact is audited (show the audit row).
- [ ] Two full rehearsals of `docs/demo-script.md` against the deployed environment, with timings and any failures logged.
- [ ] `docs/coverage-check.md` has a row for every line in the master plan's coverage table, each with evidence or an explicit gap (report counts: met / partially met / not met).
- [ ] Accessibility: Lighthouse at least 90 on key pages, keyboard-only walkthrough of the Reviewer flow (report).
- [ ] Production-config test: demo seed endpoints return `DEMO_MODE_DISABLED` when `AJNA_ENV=production` and demo mode is off.
- [ ] README lets a fresh machine run the stack; a teammate (or script) follows it and reports time to first working demo.
- [ ] Smoke monitor green after a fresh deploy (report URL checks).
