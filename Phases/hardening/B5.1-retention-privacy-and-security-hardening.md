# B5.1-retention-privacy-and-security-hardening

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `B1.1` to `B4.2`, and all `findings/P0.*` notes.

## Purpose

Prove the data protection model holds across the whole backend: consolidate retention jobs, run a full RLS test matrix, verify the audit chain on a schedule, harden the API, and close known gaps. Evidence over assertions.

## What already exists

- Foundation files and P0 findings.
- All backend features: platform and contracts (`B1.1`), DB/RLS/vaults (`B1.2`), auth/consent/audit (`B1.3`), queues and scoring (`B1.4`), wearable and radar (`B2.1`, `B2.2`), monitor flags and crisis reviews (`B3.1`), population aggregation (`B4.1`), care-gap routing and drafts (`B4.2`).
- Per-feature retention and consent-revoked handlers, built in earlier files.
- Collected "Gaps found" from all earlier handoffs (to be reviewed in this file).

## Scope

1. **Retention consolidation:** a single scheduler registering all retention jobs per `00-data-protection-model.md` section 5 (flags 30 days, crisis reviews 12 months, wearable 13 months, baselines and PRI 13 months, drafts 12 months, audit 24 months), with a dry-run mode that reports counts and a live mode.
2. **Consent revocation end to end:** verify each scope's revocation (`wearable`, `monitor_me`, `population_use`) removes or detaches the right data and stops processing.
3. **Subject deletion:** `DELETE /v1/me` (and admin equivalent) deleting the vault and DEK, detaching `subject_id` rows, closing open items; aggregates unaffected.
4. **Full RLS matrix:** auto-generated test over every table, role and operation compared with an expected-permissions file checked into the repo; CI fails on any drift.
5. **Audit chain:** scheduled `ajna.audit.verify` job (daily) that alerts on a broken chain; export of the verification report.
6. **API hardening:** per-route rate limits for auth and ingest, request size limits, strict CORS, security headers, input fuzzing on the main POST endpoints, dependency audit (npm audit, pip-audit), secret scanning in CI, log redaction regression tests.
7. **Key handling:** KEK rotation drill in staging with a before/after decrypt check; documented break-glass procedure.
8. **Gap review:** triage every "Gaps found" item from earlier handoffs into: fixed here, accepted with reason, or deferred with an owner. Add the `team_lead` role if `B3.1` depended on it.
9. **Privacy impact note** (`docs/privacy-impact.md`): data flows, classes, retention table, controls, residual risks, written for reviewers; names the data protection law(s) the team believes apply, marked "to be confirmed by counsel".
10. Update `contracts/openapi.v1.yaml` for `DELETE /v1/me` and any admin report endpoints, regenerating and linting.

## Out of scope

- Mobile and web hardening (`M5.1`, `W5.1`).
- Third-party penetration testing and formal certification (list as recommended next steps).
- Changing feature behaviour beyond fixing defects found.

## Contracts used

Reads and extends `contracts/openapi.v1.yaml`. Publishes `DELETE /v1/me`, `GET /v1/admin/audit/report` (admin); schema `AuditVerificationReport`. Does not change any existing endpoint shape.

## Data model

- `retention_runs(id uuid pk, job text, mode text, started_at, finished_at, rows_deleted int, rows_aggregated int, error text null)`
- `audit_verifications(id uuid pk, ran_at, rows_checked bigint, ok boolean, first_broken_seq bigint null)`
- `expected_permissions.yaml` (repo file): role × table × operation.

## Rules and behaviour

- Retention jobs are idempotent, batched and safe to re-run; dry-run is the default in non-production.
- Deletion never touches the audit chain (it records the deletion event).
- No test may use real health data.
- Every finding is recorded with evidence and a decision; nothing is silently accepted.
- Wording and no-automatic-action rules are re-verified by grep and tests across the repo.

## Acceptance checks

- [ ] RLS matrix: tables × roles × operations tested (report counts), mismatches versus `expected_permissions.yaml`: 0, and CI fails when a policy is deliberately weakened (show the failing run).
- [ ] Retention dry-run vs live on seeded aged data: expected vs actual deleted rows per data class (report table); aggregates unchanged.
- [ ] Revocation tests for all 3 scopes: processing stops and data removed within the configured window (report timings).
- [ ] Subject deletion: after `DELETE /v1/me`, no decryptable vault data and no `subject_id` rows outside aggregates/audit (report SQL results).
- [ ] Audit chain verification passes on 100,000 rows; a manually tampered row is detected with the correct sequence number (report both).
- [ ] KEK rotation drill: all vault items decrypt after rotation (report counts); rollback documented.
- [ ] Fuzzing: 1,000 malformed payloads per main POST endpoint return standard error shape with no 500s (report counts).
- [ ] Dependency audit and secret scan: 0 high/critical unresolved (report), or each exception recorded with a reason.
- [ ] Log redaction regression: seeded fake PHI, tokens and audio-like arrays never appear in logs from a full end-to-end run (grep result).
- [ ] Repo-wide wording grep (`diagnos`, `auto-send`, `dispatch`) outside rule text: 0; messaging SDK grep: 0.
- [ ] Gap review table complete: every earlier "Gaps found" entry has a decision.
- [ ] `docs/privacy-impact.md` written and cross-checked against the retention test results.
