# B1.3-auth-consent-and-audit

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `B1.1` and `B1.2`, `findings/P0.4-findings.md` (audit chain pattern).

## Purpose

Add authentication, the role model, per-scope revocable consent records and the hash-chained audit log. Every later backend file relies on these guards and the audit service.

## What already exists

- Foundation files and P0 findings.
- From `B1.1`: NestJS skeleton, `AppError`, request IDs, logging, rate limiting, `openapi.v1.yaml` v1.
- From `B1.2`: roles `app_user`, `app_reviewer`, `app_official`, `app_worker`, `app_admin`; tables `subjects`, `vaults`, `vault_items`; `common/crypto`; `VaultService`; transaction helper setting `app.subject_id` and `app.role`.
- No users, sessions, consents or audit rows.

## Scope

1. Auth: registration and login for end users (email + password hashed with argon2id, identity stored in the vault, only a keyed hash of the email kept for lookup), JWT access tokens (15 min) and rotating refresh tokens (30 days, stored hashed).
2. Staff accounts: Reviewer, Official and Admin roles created by an admin seed command (no public staff signup).
3. Guards: `AuthGuard`, `RolesGuard`, and a `ConsentGuard` decorator that requires an active scope for a route (`@RequiresConsent('wearable')`).
4. Consent: table, grant, revoke, history, versioned consent text. Revoking emits a `consent.revoked` event for later cleanup jobs (job handling arrives in `B1.4` and feature files).
5. Audit chain: service `AuditService.append(event)` writing canonical rows with `SHA-256(previous_hash || canonical_row)`, plus `verifyChain()` that recomputes all hashes.
6. Audit read events: a decorator that records any non-owner read of vault data.
7. Endpoints (below) and contract updates.

## Out of scope

- Wearable, flag or review features.
- Queues and workers (`B1.4`). Consent revocation here only emits an event and records the revocation.
- Social login, MFA (note under Gaps found for later).

## Contracts used

Reads and extends `openapi.v1.yaml`. Publishes:

- `POST /v1/auth/register`, `POST /v1/auth/login`, `POST /v1/auth/refresh`, `POST /v1/auth/logout`
- `GET /v1/me`
- `GET /v1/consents`, `PUT /v1/consents/{scope}` (body: `{ granted: boolean, textVersion: string }`)
- `GET /v1/admin/audit/verify` (admin only)
- Schemas: `AuthTokens`, `Me`, `Consent`, `ConsentScope` (`wearable | monitor_me | population_use`)

## Data model

- `auth_accounts(subject_id uuid pk, email_hash bytea unique, password_hash text, role text, created_at, disabled_at)`
- `refresh_tokens(id uuid pk, subject_id, token_hash bytea, expires_at, revoked_at, replaced_by uuid)`
- `consent_texts(scope text, version text, body text, published_at, primary key(scope, version))`
- `consents(id uuid pk, subject_id, scope text, granted boolean, text_version text, at timestamptz)` (append-only; current state is the latest row per scope)
- `audit_log(seq bigserial pk, at timestamptz, actor_subject_id uuid null, actor_role text, action text, target_type text, target_id uuid null, detail jsonb, prev_hash bytea, hash bytea)` (insert only; no update or delete grants)

RLS: users see only their own consent and account rows; audit log readable by `app_admin` only.

## Rules and behaviour

- Passwords: minimum 12 characters, argon2id. Login errors never reveal whether the email exists (`AUTH_INVALID_CREDENTIALS`).
- Refresh token reuse (a rotated token presented again) revokes the whole token family.
- Consent default is not granted. Granting needs the current `textVersion`; an outdated version returns `CONSENT_TEXT_OUTDATED`.
- Revocation takes effect immediately for the `ConsentGuard`.
- Audit rows contain ids and action names only. No PHI values.
- The audit table has no UPDATE or DELETE privilege for any role; `verifyChain()` detects a tampered row in a test.
- Wording: error messages use neutral language; no health claims.

## Acceptance checks

- [ ] Register, login, refresh, logout flows pass tests (report test count and coverage).
- [ ] Refresh token reuse test: second use of a rotated token returns 401 and revokes the family.
- [ ] Login with unknown email and wrong password return identical response bodies and similar timing (report the difference in ms over 100 runs).
- [ ] RolesGuard matrix: each route versus each role, actual versus expected (report mismatches: 0).
- [ ] ConsentGuard test: route returns `CONSENT_REQUIRED` without consent, succeeds after grant, fails again immediately after revoke.
- [ ] Audit chain: append 1,000 rows, `verifyChain()` passes; manually altering one row is detected and the broken sequence number reported.
- [ ] No role can UPDATE or DELETE `audit_log` (test per role).
- [ ] Email and password never appear in logs or audit rows (grep test over captured output).
- [ ] Contract regenerated, linted, and CI stale check passes; list the new endpoints.
