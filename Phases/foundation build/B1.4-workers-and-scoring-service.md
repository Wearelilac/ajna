# B1.4-workers-and-scoring-service

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `B1.1`, `B1.2`, `B1.3`, `findings/P0.1-findings.md`.

## Purpose

Add the asynchronous backbone: BullMQ on Upstash Redis with a worker process, a pending-jobs sweeper, and the FastAPI scoring service with a published internal contract. Feature files add concrete jobs and scoring routines.

## What already exists

- Foundation files and P0 findings.
- From `B1.1` to `B1.3`: NestJS API, env validation, errors, logging, roles and RLS, vault and crypto, auth, consent, audit chain, `common/limits.ts`, `contracts/openapi.v1.yaml` with health, auth, me, consents and audit verify.
- No queues, workers or scoring service.

## Scope

1. BullMQ setup in `apps/api/src/workers/`: connection to Upstash Redis, queue factory using the naming scheme `ajna.<domain>.<action>`, default retry with exponential backoff, dead-letter handling, concurrency settings informed by `P0.1` throughput limits.
2. Separate worker entrypoint, deployable as a Render Background Worker.
3. Job payload rule: ids only (`subject_id` and a record id), never PHI values. A validator rejects job data with unexpected keys.
4. `pending_jobs` outbox table and a sweeper that requeues jobs if Redis was down at enqueue time.
5. Register two infrastructure jobs: `ajna.system.heartbeat` and `ajna.privacy.consent-revoked` (a handler stub that logs the event and marks it processed; feature files fill in the data cleanup).
6. FastAPI service in `services/scoring/` with pydantic-settings env validation, the standard error shape, request IDs, JSON logging, bearer token auth (`AJNA_SCORING_TOKEN`).
7. Internal contract `contracts/scoring.internal.v1.yaml` with `GET /health`, `POST /v1/score/baseline` and `POST /v1/score/anomaly` (stub implementations returning deterministic placeholder values and `model_version: "stub-0"`).
8. NestJS client for the scoring service with timeout, retry and circuit-breaker behaviour.
9. Deploy the scoring service as a private Render service and update `GET /v1/ready` to include `redis` and `scoring` statuses.

## Out of scope

- Real baseline or PRI computation (`B2.2`).
- Wearable ingest (`B2.1`).
- Aggregation and care-gap jobs (`B4.x`).
- Retention jobs (`B5.1`).

## Contracts used

Reads `openapi.v1.yaml`; the only change is `GET /v1/ready` gaining `redis` and `scoring` status fields. Publishes the internal contract `contracts/scoring.internal.v1.yaml` (not exposed to clients).

## Data model

- `pending_jobs(id uuid pk, queue text, subject_id uuid null, record_id uuid null, status text, attempts int, created_at, enqueued_at null)`
- `processed_events(event_id uuid pk, kind text, processed_at)` (idempotency for event-driven jobs)

RLS: workers only, via `app_worker`.

## Rules and behaviour

- Idempotent jobs: processing the same job twice produces the same result and no duplicates.
- Scoring requests carry only numeric arrays and a request id, never identity or free text.
- Scoring unavailable: the API still responds, the job retries with backoff, and the state reads as `pending`.
- Redis unavailable: API writes `pending_jobs`; the sweeper requeues once Redis is back.
- Respect Upstash free-tier command limits: no busy polling; record the observed commands per minute at idle.
- If `P0.1` was `limited-go`, enforce its throughput limits as config, not as hard-coded values.

## Acceptance checks

- [ ] Worker boots, processes 1,000 heartbeat jobs; report jobs/sec and p95 latency on Render + Upstash free tiers.
- [ ] Idle Upstash command usage per hour (report number and the free-tier limit).
- [ ] Redis outage test: stop Redis (or point to a bad URL), enqueue 50 jobs, restore, confirm all 50 processed exactly once.
- [ ] Job payload validator rejects unknown keys and any value that looks like an email or phone (report test cases).
- [ ] Scoring service: bad token returns the standard error shape with 401; missing env var prevents boot.
- [ ] Contract test: NestJS client versus `scoring.internal.v1.yaml` generated types, with CI check for drift.
- [ ] Circuit breaker test: scoring returns 500 five times, then calls are short-circuited, and recover after cool-down (report timings).
- [ ] `GET /v1/ready` reports `redis` and `scoring` and degrades without crashing when either is down.
- [ ] pytest and jest suites pass; report counts.
