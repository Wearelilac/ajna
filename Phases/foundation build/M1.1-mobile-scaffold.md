# M1.1-mobile-scaffold

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoff of `B1.1`, `findings/P0.2-findings.md`.

## Purpose

Create the Expo mobile app shell that all mobile features build on: development build setup, styling, navigation, state and data layers, and a typed API client generated from the contract. Runs in parallel with `B1.2` to `B1.4`; it only reads the published contract.

## What already exists

- Foundation files and P0 findings (P0.2 verdict `<verdict>`, chosen audio library and model runtime `<names>`).
- From `B1.1`: `contracts/openapi.v1.yaml` v1 (`GET /v1/health`, `GET /v1/ready`, `ErrorResponse`, `bearerAuth`). The API is deployed.
- No mobile code.

## Scope

1. Create `apps/mobile` with Expo SDK 52+, TypeScript strict, Expo Router, and a **development build** configuration (EAS profile) including the native modules chosen in `P0.2` (declared but unused here).
2. NativeWind setup with a small design token file (colours, spacing, radii, typography) and a calm, privacy-forward visual identity for Ajna.
3. react-native-reanimated configured.
4. State: zustand stores for app state (`session`, `ui`). Server state: TanStack Query with a shared query client and retry policy.
5. API client generated from `contracts/openapi.v1.yaml` with `openapi-typescript` plus a thin fetch wrapper in `src/api/`; CI fails if the generated client is stale.
6. Error handling: a single mapper from `ErrorResponse` to user-safe messages, branching on `code`; the app shows the `requestId` in a "details" sheet for support.
7. Navigation skeleton: tabs for **Radar** (Feature A), **Monitor Me** (Feature B), **Privacy** (consents and data), **Settings**; each tab shows a placeholder screen.
8. Health screen in Settings that calls `GET /v1/health` and `GET /v1/ready` (proves the client wiring).
9. Create the empty `src/edge/` folder with the import-isolation lint rule already enabled (no network, filesystem, storage or logging imports allowed there) and a unit test proving the rule fires.

## Out of scope

- Sign-in, consent screens, secure storage (`M1.2`).
- Any wearable or acoustic code (`M2.1`, `M3.x`).
- Push notifications.

## Contracts used

Reads only `contracts/openapi.v1.yaml` (v1 plus any later version when regenerated). Does not publish or edit any contract.

## Data model

Client-side state:

- `useUiStore { theme, reducedMotion, lastErrorRequestId }`
- `useSessionStore { status: 'signed_out' | 'signed_in', subjectId?: string }` (populated in `M1.2`)
- Query keys namespaced `['health']`, `['ready']`, with more added later.

## Rules and behaviour

- The app never calls an endpoint missing from the generated client.
- UI copy follows the wording rules: "flagged for review", never "diagnosed". A lint test runs a banned-word grep over `src/`.
- Accessibility: minimum touch target 44pt, dynamic type respected, reduced motion respected.
- Keep `src/edge/` empty of logic in this file, with only the lint rule and a README note stating its rules.
- Expo Go is not supported; the README explains the development build steps.

## Acceptance checks

- [ ] Development build installs and launches on one Android device and one iPhone (name them); report build times.
- [ ] Tabs navigate; the health screen shows live `health` and `ready` results from the deployed API (screenshot or log excerpt).
- [ ] Generated client matches the contract; the CI stale-check fails when the contract changes without regeneration (show the failing run).
- [ ] Error mapper unit tests cover at least 6 `code` values and an unknown code fallback.
- [ ] Lint rule test: adding `import fetch` or `fs` inside `src/edge/` fails lint (show output).
- [ ] Banned-word grep over `src/` returns 0 matches.
- [ ] Cold start time on the mid-range Android device (report seconds) and JS bundle size (MB).
- [ ] Accessibility check: screen reader reads all tab labels (report the device and result).
