# M1.2-mobile-auth-consent-and-secure-storage

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `M1.1` and `B1.3`.

## Purpose

Add sign-in, per-scope consent screens and secure token storage to the mobile app, using only endpoints published by `B1.3`.

## What already exists

- Foundation files and P0 findings.
- From `M1.1`: Expo app shell, tabs (Radar, Monitor Me, Privacy, Settings), NativeWind tokens, zustand stores, TanStack Query, generated client, error mapper, `src/edge/` lint rule.
- From `B1.3` (read through the contract): `POST /v1/auth/register|login|refresh|logout`, `GET /v1/me`, `GET /v1/consents`, `PUT /v1/consents/{scope}`; schemas `AuthTokens`, `Me`, `Consent`, `ConsentScope`.
- No sign-in or consent UI.

## Scope

1. Auth screens: register, login, logout, with clear, plain-language privacy copy.
2. Secure storage: access and refresh tokens in `expo-secure-store`; nothing health-related stored unencrypted. A single `tokenStore` module owns it.
3. Token refresh: automatic refresh through a fetch interceptor with a single-flight refresh lock; on refresh failure, sign out.
4. Session bootstrap: on launch, restore the session, call `GET /v1/me`, and route to tabs or auth.
5. Consent UI in the **Privacy** tab: three scopes (`wearable`, `monitor_me`, `population_use`), each with plain text, current version, a toggle, and history. Granting shows the full consent text first; revoking is one tap with confirmation.
6. Monitor Me gating: the Monitor Me tab shows a locked state with a link to consent when `monitor_me` is not granted (no session start possible yet).
7. Sign-out clears tokens, query cache and zustand state.

## Out of scope

- Wearable screens (`M2.1`), monitor session behaviour (`M3.x`), biometrics, MFA, social login.

## Contracts used

Reads `contracts/openapi.v1.yaml` as published by `B1.3`. Publishes nothing. If something needed is missing, record it under "Gaps found" and stop; never add a client-side endpoint.

## Data model

Client-side only:

- Secure store keys: `ajna.accessToken`, `ajna.refreshToken`
- `useSessionStore { status, subjectId, role }`
- Query keys: `['me']`, `['consents']`
- `useConsentUi { pendingScope?, showingTextFor? }`

## Rules and behaviour

- Consent is never granted implicitly, never bundled, never pre-ticked.
- Plain-language copy for each scope, including what leaves the device. For `monitor_me`: "Audio is analysed on your phone and instantly discarded. Only a small de-identified signal may be sent. Raw audio never leaves your phone."
- No tracking SDKs. No analytics that include user identifiers.
- Error messages from `code`, never raw `message` unless the contract marks it safe.
- UI wording passes the banned-word lint.

## Acceptance checks

- [ ] Register, login, logout and session restore verified on device (named) against the deployed API (report the steps and results).
- [ ] Tokens appear only in secure store: a test inspects AsyncStorage/MMKV and files for token strings and finds none (report what was scanned).
- [ ] Refresh test: expire the access token, make 5 concurrent requests, observe exactly 1 refresh call (report the count).
- [ ] Consent toggles round trip to the API: grant, revoke, history list match server state (report for all 3 scopes).
- [ ] Monitor Me tab is locked without consent and unlocked after grant, and re-locks after revoke.
- [ ] Sign-out wipes tokens, query cache and stores (test asserts empty state).
- [ ] No endpoint used outside the contract: client lint reports 0 hand-written fetch paths.
- [ ] Banned-word grep: 0 matches. Accessibility: all inputs labelled (report screen reader pass).
