# W1.1-dashboard-scaffold

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `B1.1` and `B1.3`.

## Purpose

Create the Next.js 15 staff dashboard shell for Reviewers and Officials: App Router layout, Tailwind, staff sign-in, role-based routing and a typed client from the contract. Runs in parallel with the other foundation files and only reads the published contract.

## What already exists

- Foundation files and P0 findings.
- From `B1.1`: `contracts/openapi.v1.yaml` v1, deployed API.
- From `B1.3` (via the contract): auth endpoints, `GET /v1/me`, roles `app_reviewer`, `app_official`, `app_admin`.
- No web code.

## Scope

1. Create `apps/web` with Next.js 15 (App Router), TypeScript strict, Tailwind CSS.
2. Typed client from `contracts/openapi.v1.yaml` in `src/api/` with a CI stale-check.
3. Staff sign-in page using `POST /v1/auth/login`; tokens in httpOnly, secure, same-site cookies set via a Next route handler (not in localStorage).
4. Middleware for role-based routing: Reviewer to `/review/*`, Official to `/population/*`, Admin to `/admin/*`; unauthorised access renders a standard "not permitted" page.
5. App shell: sidebar, top bar with role label, session expiry handling, and a permanent footer line: "Advisory indicators for human review. Not a diagnosis."
6. Placeholder pages per route group (`/review`, `/population`, `/admin`) so later `W` files drop in.
7. Error boundary and mapper from `ErrorResponse` showing the `requestId`.
8. Basic accessibility and responsive layout (desktop-first, usable on tablet).

## Out of scope

- Crisis review UI (`W3.1`), population dashboard (`W4.1`), care-gap and outreach UI (`W4.2`).
- End-user (patient) pages. This app is for staff only.

## Contracts used

Reads `contracts/openapi.v1.yaml` as published by `B1.1` and `B1.3`. Publishes nothing.

## Data model

Client-side only:

- Cookie `ajna_session` (httpOnly) holding the access token; refresh handled in a route handler.
- `Me { subjectId, role }` fetched server-side per request.
- Route groups: `(auth)`, `(staff)/review`, `(staff)/population`, `(staff)/admin`.

## Rules and behaviour

- Officials never reach pages that request row-level data; the role check happens in middleware and again in each server component.
- UI copy follows the wording rules and the banned-word grep runs in CI.
- No third-party analytics or trackers.
- Server components fetch with the user's cookie token; nothing is cached across users (`cache: 'no-store'` for authenticated data).
- Sessions expire cleanly: a 401 triggers one refresh attempt then sign-out.
