# M2.1-resilience-radar-screens

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `M1.1`, `M1.2`, `B2.1`, `B2.2`.

## Purpose

Build the Radar tab: the user's daily metrics, Personal Resilience Index, trend and deviation flags, with a demo data option, using only published endpoints. All wording is advisory.

## What already exists

- Foundation files and P0 findings.
- From `M1.1` and `M1.2`: Expo app, tabs, NativeWind tokens, generated client, error mapper, auth, secure store, consent UI, `src/edge/` lint rule.
- From `B2.1` and `B2.2` (read via the contract): `POST /v1/wearable/demo-seed`, `GET /v1/wearable/daily`, `GET /v1/radar/summary`, `GET /v1/radar/pri`, `GET /v1/radar/deviations`; schemas `WearableDaily`, `RadarSummary`, `PriPoint`, `DeviationFlag`.
- Radar tab is a placeholder.

## Scope

1. Radar home: today's Personal Resilience Index (large, with plain explanation), 14/30-day sparkline, and a short list of any active deviation flags.
2. Metric cards for HRV, skin temperature deviation, resting HR, sleep architecture, activity recovery, each showing today versus personal baseline band (mean ± 3 SD shading) using the daily and deviation endpoints.
3. Flag detail sheet: which metric, direction, how far from your usual, and "What this means": "This is an advisory indicator for human review, not a diagnosis. Consider rest, hydration and talking with your usual care provider if you feel unwell."
4. Consent gate: if `wearable` consent is missing, show the consent explanation and a button to the Privacy tab.
5. Demo data: "Load demo data" button (visible when the API allows it) with scenario picker (`steady`, `gradual_decline`, `acute_deviation`) calling `POST /v1/wearable/demo-seed`, then polling `GET /v1/radar/summary` until ready.
6. Empty, loading, stale (`isStale`) and error states; pull to refresh.
7. Charts with `react-native-svg` or a Victory Native chart library (flag under Gaps found if outside the stack), using reanimated for transitions, honouring reduced motion.

## Out of scope

- Real wearable connection or vendor OAuth.
- Notifications about flags.
- Monitor Me (`M3.x`).
- Any sending of flags to a clinician.

## Contracts used

Reads only: `openapi.v1.yaml` endpoints and schemas listed above. Publishes nothing. If something is missing, record it under Gaps found and stop; do not invent endpoints.

## Data model

Client-side:

- Query keys `['radar','summary']`, `['radar','pri', range]`, `['radar','deviations', range]`, `['wearable','daily', range]`
- `useRadarUi { range: 14 | 30, selectedMetric }`
- No persistence of metrics on device beyond the TanStack Query in-memory cache (cache cleared on sign-out and on app backgrounding beyond 5 minutes).

## Rules and behaviour

- Wording: "flagged for review", "elevated indicator", "advisory". Never "diagnosed", "you have", "risk of [condition]".
- No red alarm styling for deviation flags; use calm amber/indigo and neutral language.
- The PRI is shown as one number with an explainer, never as a "health score" claim.
- Respect dynamic type and screen readers; every chart has a text summary.
- Do not log metric values.
