# W3.1-crisis-review-console

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `W1.1` and `B3.1`, `findings/P0.4-findings.md` (review workflow pattern).

## Purpose

Build the Reviewer console for the crisis review queue: staff see de-identified flag items, take ownership, record outcomes and, only with a recorded reason, reveal contact details. No automated actions.

## What already exists

- Foundation files and P0 findings.
- From `W1.1`: Next.js 15 shell, staff sign-in via httpOnly cookie, role middleware, `/review` placeholder, error boundary, advisory footer, generated client.
- From `B3.1` (read via the contract): `GET /v1/crisis-reviews`, `GET /v1/crisis-reviews/{id}`, `POST /v1/crisis-reviews/{id}/assign`, `POST /v1/crisis-reviews/{id}/transition`, `POST /v1/crisis-reviews/{id}/reveal-contact`; schemas `CrisisReview`, `CrisisReviewState`, `CrisisOutcome`; error `REVIEW_TRANSITION_INVALID`.
- No review UI.

## Scope

1. Queue page `/review`: table of items with state, owner, flag count, last flag time, age and SLA status; filters (state, owner = me/unassigned/all) and sorting; auto-refresh every 30 seconds.
2. Detail page `/review/[id]`: signature summary, confidence band, counts over time (a small timeline of hour buckets), state history from `crisis_review_events`, owner and notes.
3. Actions: Assign to me, Start review, Record outcome (`no_action`, `routine_follow_up_requested`, `escalated_to_clinical_lead`) with required reason text, Close. Buttons shown only when the transition is legal, and API errors shown through the error mapper.
4. Reveal contact: guarded modal requiring a typed reason and a confirmation; calls `POST /v1/crisis-reviews/{id}/reveal-contact`; the revealed contact is shown for the current page view only and is not cached.
5. Team lead view: items flagged `escalated_to_lead` appear in a distinct list for users with the lead role (role check from the contract's `Me` schema; if the role does not exist yet, record under Gaps found).
6. Safety notices on every page: "Advisory indicators for human review. Not a diagnosis. This console does not contact the user or emergency services." plus a link to the organisation's own crisis procedure (configurable URL).
7. Accessible, keyboard-friendly table and dialogs.

## Out of scope

- Outreach messaging, calling or any direct contact from Ajna.
- Population views (`W4.1`) and care-gap/outreach review (`W4.2`).
- Editing flags or deleting reviews.

## Contracts used

Reads only the `B3.1` endpoints and schemas listed above, plus `GET /v1/me`. Publishes nothing.

## Data model

Client-side only:

- URL state for filters and sorting
- React Query/server components with `cache: 'no-store'`
- No browser storage of review content or contacts.

## Rules and behaviour

- Role check in middleware and in each server component: only `app_reviewer` (and admin where the contract permits) can access `/review/*`; Officials get the not-permitted page.
- Wording: "flagged for review", "item", "owner"; never "diagnosed", "patient in crisis", "alert dispatched".
- There is no button, link or code path that sends a message, calls a person or triggers an external service from this console.
- Reveal-contact requires a reason; empty or very short reasons are blocked client-side and server-side.
- The UI shows who owns each item; unowned items are visually distinct but not alarmist.

## Acceptance checks

- [ ] Reviewer can list, filter, assign, review, record outcome and close an item end to end on seeded data (report the steps and final state).
- [ ] Illegal transitions are not offered in the UI and, if forced, produce the `REVIEW_TRANSITION_INVALID` message (report both).
- [ ] Reveal-contact: without a reason blocked; with a reason succeeds; an audit row exists (query result) and the contact is not present in cache or storage afterwards (test).
- [ ] Role matrix: Reviewer allowed; Official and unauthenticated blocked (report mismatches: 0).
- [ ] Static check: grep for `fetch(` to undeclared paths and for any messaging/telephony SDK returns 0.
- [ ] Wording lint: 0 banned words; disclaimer present on all pages (route test).
- [ ] Accessibility: Lighthouse at least 90, keyboard-only walkthrough of the full flow (report result).
- [ ] Queue page loads in under 2 seconds with 500 items (report ms).
- [ ] SLA display correct for items older and newer than `AJNA_REVIEW_SLA_MIN` (report 2 cases).
