# B3.1-deidentified-flag-ingest-and-review-queue

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `B1.1` to `B1.4`, `findings/P0.2-findings.md` (verdict `<verdict>`, limits, recommended threshold and session cap), `findings/P0.4-findings.md` (review state machine pattern).

## Purpose

Receive the only thing Feature B ever sends, the de-identified flag, enforce the field allow-list, and route it into a human-owned crisis review queue. Also record monitor sessions (metadata only) so session caps and consent can be enforced server-side. **Build this before `M3.2`**, which reads the endpoints published here.

## What already exists

- Foundation files and P0 findings.
- From `B1.1` to `B1.4`: API platform, DB/RLS/vaults, auth/consent/audit, queues and scoring service.
- From `B2.x`: wearable and radar features (not used here).
- No monitor or crisis tables or endpoints.

## Scope

1. Monitor session endpoints: `POST /v1/monitor/sessions` (start; requires `monitor_me` consent; returns `sessionId`, server-side `maxDurationSec` from P0.2 limits), `POST /v1/monitor/sessions/{id}/end`.
2. Flag ingest: `POST /v1/monitor/flags` accepts exactly the allow-list from `00-data-protection-model.md` section 1 and nothing else. Unknown fields return `FLAG_FIELD_NOT_ALLOWED`. Requires active `monitor_me` consent and an open session; `time_bucket` is truncated to the hour server-side.
3. Rate and sanity limits: max flags per session per hour, confidence in range, model version in an allow-list.
4. Crisis review items: each accepted flag of a configurable severity set (for example `distress_signature` with confidence above the threshold) creates or joins a `crisis_reviews` item for that subject within a rolling window (grouping repeated flags).
5. State machine `new → assigned → in_review → closed`, with outcomes (`no_action`, `routine_follow_up_requested`, `escalated_to_clinical_lead`); every transition records the actor, reason and audit row. No automatic transition to any external action.
6. Ownership: items have `owner_id` (Reviewer) once assigned; items unassigned after `AJNA_REVIEW_SLA_MIN` escalate to a `team_lead` queue flag (notification to staff only; no patient or emergency contact).
7. Endpoints for staff: `GET /v1/crisis-reviews` (filters: state, owner), `GET /v1/crisis-reviews/{id}`, `POST /v1/crisis-reviews/{id}/assign`, `POST /v1/crisis-reviews/{id}/transition`.
8. Re-identification: a Reviewer can request identity link only with a recorded reason (`POST /v1/crisis-reviews/{id}/reveal-contact`), which writes an audit row and returns only what the vault holds for contact purposes.
9. Retention job `ajna.monitor.flag-retention` (30-day row-level retention) and implementation of the `monitor_me` branch of the consent-revoked handler (detach and delete the subject's flags and open sessions).

## Out of scope

- The on-device engine (`M3.1`), the session UX (`M3.2`), the staff console (`W3.1`).
- Any automatic message to a user, any emergency dispatch, any call to emergency services.
- Population aggregation of flags (`B4.1`).

## Contracts used

Reads `openapi.v1.yaml`. Publishes: `POST /v1/monitor/sessions`, `POST /v1/monitor/sessions/{id}/end`, `POST /v1/monitor/flags`, `GET /v1/crisis-reviews`, `GET /v1/crisis-reviews/{id}`, `POST /v1/crisis-reviews/{id}/assign`, `POST /v1/crisis-reviews/{id}/transition`, `POST /v1/crisis-reviews/{id}/reveal-contact`; schemas `MonitorSession`, `DeIdentifiedFlagInput`, `CrisisReview`, `CrisisReviewState`, `CrisisOutcome`. Error codes: `FLAG_FIELD_NOT_ALLOWED`, `MONITOR_SESSION_REQUIRED`, `MONITOR_SESSION_EXPIRED`, `REVIEW_TRANSITION_INVALID`.

## Data model

- `monitor_sessions(id uuid pk, subject_id uuid, started_at, ended_at null, max_duration_sec int, end_reason text null)`
- `deidentified_flags(id uuid pk, subject_id uuid, session_id uuid, signature text, confidence numeric(3,2), time_bucket timestamptz, model_version text, created_at)` (matches the allow-list exactly)
- `crisis_reviews(id uuid pk, subject_id uuid, state text, owner_id uuid null, outcome text null, first_flag_at, last_flag_at, flag_count int, closed_at null, escalated_to_lead boolean default false)`
- `crisis_review_events(id uuid pk, review_id uuid, from_state text, to_state text, actor_id uuid, reason text, at timestamptz)`
- RLS: users cannot read flags; `app_reviewer` reads assigned/unassigned items without identity; officials have no access.

## Rules and behaviour

- No audio, audio features or transcripts can be sent: the schema has no field for them, and the endpoint rejects unknown fields.
- A crisis review is a **workflow for a human**, with a named owner. Responses and UI strings say "flagged for review"; there is no value meaning "emergency dispatched".
- No automatic outbound message and no automatic external action of any kind. The queue notifies staff only.
- Flags are accepted only while a session is open and consented; a late flag after consent revocation returns `CONSENT_REQUIRED`.
- The Reviewer sees the signature, confidence, time bucket and counts, not the user's identity, until `reveal-contact` is used with a reason.
- Every state change and every reveal writes the audit chain.

## Acceptance checks

- [ ] Allow-list test: a payload with each of 10 extra fields (for example `audio`, `features`, `transcript`, `lat`, `lng`, `duration`, `loudness`, `device_id`, `text`, `speaker_count`) is rejected with `FLAG_FIELD_NOT_ALLOWED` (report 10 of 10).
- [ ] Consent/session test: no consent, closed session or expired session each return the expected error code (report 3 cases).
- [ ] `time_bucket` stored truncated to the hour (report a query result).
- [ ] State machine: legal transitions pass, illegal ones return `REVIEW_TRANSITION_INVALID` (report the matrix).
- [ ] Unassigned past SLA flips `escalated_to_lead` and does not trigger any outbound message (test asserts no call to any messaging/notification-to-user module).
- [ ] Reveal test: reveal without reason fails; with reason writes an audit row (show it); `verifyChain()` passes.
- [ ] RLS matrix for all new tables by role (report mismatches: 0).
- [ ] Retention job removes flags older than 30 days and the review record keeps only counts and outcome (report before/after).
- [ ] Consent revocation deletes the subject's flags and ends open sessions within the configured window (report timing).
- [ ] Wording lint and grep for `diagnos`, `dispatch`, `emergency` in API strings: 0 matches outside this file's rule text.
- [ ] Load test at the `P0.2`/`P0.1` limits: report flags/sec and p95 latency.
