# W4.2-care-gap-and-outreach-review

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `W1.1`, `W3.1` and `B4.2`, `findings/P0.4-findings.md`.

## Purpose

Build the staff workspace for care gaps: a worklist of overdue Well-Child Visits and screenings, the pathway match for each, the generated outreach draft, and a review flow where a human approves, edits or rejects. Nothing is sent from Ajna.

## What already exists

- Foundation files and P0 findings.
- From `W1.1`: Next.js shell, staff auth, role middleware, advisory footer, generated client.
- From `W3.1`: queue/detail patterns, reveal-contact modal component, safety notice component.
- From `B4.2` (read via the contract): `GET /v1/care-pathways`, `GET /v1/care-gaps(+/{id})`, `GET /v1/outreach-drafts(+/{id})`, `PUT /v1/outreach-drafts/{id}/body`, `POST /v1/outreach-drafts/{id}/transition`, `POST /v1/outreach-drafts/{id}/reveal-contact`, `PUT /v1/admin/care-pathways/{id}`; schemas `CarePathway`, `CareGap`, `PathwayMatch`, `OutreachDraft`, `DraftState`; errors `DRAFT_TRANSITION_INVALID`, `DRAFT_LINT_FAILED`.
- No care-gap UI.

## Scope

1. `/review/care-gaps`: worklist table with gap type, due date, age band, community, match status (matched, `no_suitable_pathway`), draft state; filters and sorting.
2. Care gap detail `/review/care-gaps/[id]`: gap summary (no raw signal data), top-k pathway matches with similarity and the eligibility filters applied, selected pathway, and the draft.
3. Draft editor: side-by-side original vs edited text, live banned-wording check, character count, language label; edits saved with `PUT /v1/outreach-drafts/{id}/body`.
4. Review actions: Start review, Approve, Edit and approve, Reject (reason required), Close; only legal transitions are offered.
5. "Approved" state clearly labelled "Approved for staff to use. Ajna does not send messages." with a copy-to-clipboard action for the approved text; the copy action is logged through an audit-safe API if the contract provides it (if not, record under Gaps found and keep copy local only).
6. `no_suitable_pathway` handling: a manual pathway picker limited to active, approved pathways from `GET /v1/care-pathways`.
7. Reveal contact modal reused from `W3.1` (reason required) so staff can contact the person through their own channels outside Ajna.
8. Admin area `/admin/pathways`: list and edit pathways with `approved_by` and `approved_on` required; placeholder-content banner until clinical sign-off is recorded.
9. Safety/wording notice on every page.

## Out of scope

- Any sending integration, scheduling or tracking of message delivery.
- Population dashboard (`W4.1`).
- Clinical content authoring workflow beyond simple pathway editing.

## Contracts used

Reads only the `B4.2` endpoints and schemas above plus `GET /v1/me`. Publishes nothing.

## Data model

Client-side only: URL state, server fetch with no-store, form state for the editor. No storage of drafts or contacts in the browser.

## Rules and behaviour

- Roles: Reviewer for `/review/care-gaps/*`, Admin for `/admin/pathways`; Officials blocked.
- Wording rules apply to the UI and to the live editor check; flagged phrases block approval until fixed.
- No button, link, form or API call sends a message anywhere. A static test asserts it.
- Reasons are required for rejection and reveal; short or empty reasons are blocked.
- Draft text never references signals, flags, audio or distress; the editor warns if staff add such terms.

## Acceptance checks

- [ ] End to end on seeded data: open a care gap, review the match, edit the draft, approve, close (report final state and audit rows).
- [ ] Illegal transitions are not offered; forced calls return `DRAFT_TRANSITION_INVALID` and show a clear message (report both).
- [ ] Editor lint: inserting 5 banned phrases is flagged and blocks approval (report 5 of 5).
- [ ] `no_suitable_pathway` flow works and lists only approved, active pathways (report counts).
- [ ] Reveal modal requires a reason and writes an audit row (query result).
- [ ] Static check: no messaging/telephony SDK, no `mailto:`/`tel:`/`sms:` links in the app, no fetch to undeclared paths (grep, 0 matches).
- [ ] Role matrix: Reviewer allowed, Admin allowed for pathways, Official blocked (mismatches: 0).
- [ ] Worklist loads in under 2 seconds with 1,000 gaps (report ms).
- [ ] Banned-word grep 0; disclaimers present on all pages (route test); Lighthouse accessibility at least 90.
