# W4.1-population-risk-dashboard

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `W1.1` and `B4.1`, `findings/P0.3-findings.md`.

## Purpose

Build the Population Risk Dashboard for public health officials: community-level risk trends, underserved-community clusters, similar-community comparison and care-gap counts, all from suppressed aggregates.

## What already exists

- Foundation files and P0 findings.
- From `W1.1`: Next.js 15 shell, staff auth cookies, role middleware, `/population` placeholder, advisory footer, error boundary, generated client.
- From `B4.1` (read via the contract): `GET /v1/population/overview`, `/communities`, `/communities/{id}`, `/communities/{id}/similar`, `/clusters`; schemas `PopulationOverview`, `CommunitySummary`, `CommunityTrend`, `ClusterSummary`, `SuppressedCell`; `POST /v1/admin/demo/population-seed` (admin).
- No dashboard pages.

## Scope

1. `/population` overview: headline tiles (communities covered, share with elevated indicators, median PRI trend, overdue care-gap share), data freshness stamp (`computedAt`), and suppression notice.
2. Community explorer: sortable, filterable table (region, cluster, age band), with a map or grid view (map library flagged under Gaps found if outside the stack; a regional grid is an acceptable fallback).
3. Community detail `/population/communities/[id]`: trend charts (weekly flags, mean PRI, deviation share), age-band breakdown, care-gap counts, cluster membership and its score breakdown, "similar communities" list.
4. Underserved clusters view: cluster list with plain-language descriptions and the factors behind each cluster.
5. Suppressed cells shown clearly ("Fewer than 10 people: not shown") and never as zero.
6. Filters in URL state; export of the currently displayed aggregate table as CSV (aggregates only, suppressed cells stay suppressed).
7. Admin-only demo control: "Load demo population" calling the seed endpoint with a confirm dialog.
8. Responsive, readable charts with text alternatives.

## Out of scope

- Row-level data, individual search, anything identity-related.
- Care-gap worklist and drafts (`W4.2`).
- Crisis review (`W3.1`).
- Predictions of individual outcomes.

## Contracts used

Reads only the `B4.1` endpoints and schemas above plus `GET /v1/me`. Publishes nothing.

## Data model

Client-side only:

- URL search params for filters and sort
- Server-side fetch with `cache: 'no-store'`; no browser storage of data.

## Rules and behaviour

- Officials see aggregates only; there are no links from this area to review or draft detail pages.
- Wording: "elevated indicator", "higher than peers", "flagged for review"; never "diagnosed", "infected", "patients at risk of [condition]".
- Every page shows the footer advisory and a link to a methods note (how suppression, aggregation and clustering work; written as a static page in this file).
- CSV export contains only values already visible and is blocked when it would include an unsuppressed cell under K.
- Accessibility: no colour-only encoding; charts have table fallbacks.

## Acceptance checks

- [ ] Officials can browse overview, explorer, detail and clusters with seeded data (report pages checked).
- [ ] Suppression UI test: communities seeded below K appear as suppressed everywhere, including charts and CSV (report 5 cases).
- [ ] Role matrix: Official allowed; Reviewer and unauthenticated blocked per route policy (mismatches: 0).
- [ ] Static check: no calls to row-level endpoints, no reference to subject identifiers (grep, 0 matches).
- [ ] CSV export test: contents equal the visible table; no suppressed value leaks (report diff).
- [ ] Performance: overview under 2 seconds and detail under 2 seconds at the P0.3-supported scale (report ms).
- [ ] Banned-word grep 0 matches; methods note and advisory footer on all pages (route test).
- [ ] Lighthouse accessibility at least 90; keyboard and screen reader pass on charts' text fallbacks (report).
- [ ] No browser storage of data (storage inspection after a session).
