# B4.2-care-gap-routing-and-outreach-drafts

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoffs of `B1.x`, `B2.2`, `B3.1`, `B4.1`, `findings/P0.3-findings.md`, `findings/P0.4-findings.md` (verdict `<verdict>`, mapping accuracy, draft approach, review state machine).

## Purpose

Detect overdue Well-Child Visits and adult screenings, map risk indicators to **approved** care pathways with pgvector, generate tailored outreach **drafts**, and run them through a human review state machine. Ajna never sends anything.

## What already exists

- Foundation files and P0 findings (pathway library schema, mapping approach, draft generation approach, state machine).
- From `B1.x` to `B4.1`: platform, auth/consent/audit, vaults, queues and scoring, radar and flag data, population aggregates and pgvector setup.
- No pathway, care-gap or draft tables, and no staff endpoints for them.

## Scope

1. Tables and migrations for pathways, care history, care gaps, matches, drafts and reviews (Data model).
2. Pathway library admin: `PUT /v1/admin/care-pathways/{id}` (admin only), with `approved_by` and `approved_on` required; seed the P0.4 synthetic library marked as placeholder content needing clinical sign-off.
3. Care-gap detection job `ajna.caregap.detect` (daily): finds overdue Well-Child Visits and adult screenings from `care_history` against pathway schedules, for subjects with `population_use` consent and an outreach-eligible flag; creates `care_gaps` with an indicator summary (no raw metric values, no audio-derived detail).
4. Mapping job `ajna.caregap.match`: hard eligibility filters first (age band, indicator type), then pgvector similarity over pathway embeddings; stores top-k with similarity; `no_suitable_pathway` goes straight to a human worklist.
5. Draft generation job `ajna.caregap.draft`: template-driven (plus optional constrained LLM polish if P0.4 used one; flag under Gaps found), tailored by age band, language and tone; passes the banned-wording lint before saving; sensitive signal details are never mentioned.
6. Review state machine from P0.4: `draft → in_review → approved | edited_approved | rejected → closed`; every transition requires a Reviewer, a reason where specified and writes the audit chain. Approval records a decision only.
7. Endpoints for Reviewers: care-gap worklist and detail, draft list/detail, edit body, transition; for Admins: pathway upsert; for Officials: aggregate care-gap counts (add into `B4.1` views if needed through a view, no new row-level access).
8. Re-identification: `reveal-contact` pattern from `B3.1` reused for outreach (reason required, audited).
9. Consent revocation handler: `population_use` revocation removes the subject from future detection and closes open drafts as `rejected` with reason `consent_withdrawn`.

## Out of scope

- Sending any SMS, email, letter or push message. No messaging provider is integrated, in this file or any other.
- UI (`W4.2`).
- Clinical content authoring (placeholder pathways only).
- EHR integration.

## Contracts used

Reads `openapi.v1.yaml`. Publishes: `GET /v1/care-pathways`, `PUT /v1/admin/care-pathways/{id}`, `GET /v1/care-gaps`, `GET /v1/care-gaps/{id}`, `GET /v1/outreach-drafts`, `GET /v1/outreach-drafts/{id}`, `PUT /v1/outreach-drafts/{id}/body`, `POST /v1/outreach-drafts/{id}/transition`, `POST /v1/outreach-drafts/{id}/reveal-contact`; schemas `CarePathway`, `CareGap`, `PathwayMatch`, `OutreachDraft`, `DraftState`. Error codes: `DRAFT_TRANSITION_INVALID`, `DRAFT_LINT_FAILED`, `PATHWAY_NOT_APPROVED`.

## Data model

- `care_pathways(id text pk, title text, eligibility jsonb, description text, wording_snippets jsonb, owner_role text, approved_by text, approved_on date, embedding vector(<N>), active boolean)`
- `care_history(subject_id uuid, service_type text, last_done date null, due_date date null, primary key(subject_id, service_type))` (PHI-adjacent; owner/worker RLS; encrypted detail in vault if it contains notes)
- `care_gaps(id uuid pk, subject_id uuid, gap_type text, due_date date, indicator_summary jsonb, status text, created_at)`
- `pathway_matches(care_gap_id uuid, pathway_id text, rank smallint, similarity numeric(5,4), filtered_by jsonb, primary key(care_gap_id, pathway_id))`
- `outreach_drafts(id uuid pk, care_gap_id uuid, pathway_id text, body text, language text, state text, generated_by text, created_at)`
- `draft_reviews(id uuid pk, draft_id uuid, reviewer_id uuid, from_state text, to_state text, reason text null, edited_body text null, at timestamptz)`
- RLS: Reviewers see items without identity; workers write; Officials none on these tables.

## Rules and behaviour

- Only active, approved pathways can be matched (`PATHWAY_NOT_APPROVED` otherwise).
- Draft wording: "may benefit from", "is due for", "we would like to offer"; never "diagnosed", never "we detected", and never a hint that audio or distress signals led to the message.
- Drafts start as `draft`. There is no auto-approve, no timer approval and no send. A static test asserts no messaging provider import exists in the repo.
- If an LLM is used, it only receives approved pathway snippets and the age band, never identifiers or signal data.
- Every transition writes the audit chain; `verifyChain()` passes after test runs.
- If P0.4 was `limited-go`, apply its limits (for example "templates only, no LLM") via config.

## Acceptance checks

- [ ] Seeded overdue cases found correctly: report seeded vs detected counts for Well-Child Visits and adult screenings (100% expected).
- [ ] Mapping accuracy on the 200-case P0.4 labelled set reproduced in production code: top-1 and top-3 (within 2 points of P0.4).
- [ ] Eligibility test: a pathway outside the age band is never returned even if most similar (report test name and result).
- [ ] 100 generated drafts: banned-wording lint violations 0, no draft mentions signals or flags (report counts).
- [ ] State machine matrix: all legal transitions pass, all illegal ones return `DRAFT_TRANSITION_INVALID` (report matrix).
- [ ] No-send proof: grep for messaging/telephony/email SDK imports returns 0, and approval test shows no outbound network call (report).
- [ ] Reveal-contact requires a reason and writes an audit row (show it); `verifyChain()` passes.
- [ ] Consent revocation closes open drafts with reason `consent_withdrawn` (report counts).
- [ ] RLS matrix for new tables by role (mismatches: 0).
- [ ] Throughput: detect+match+draft for 10,000 care gaps completes in a reported time within the P0.4/P0.1 budget.
- [ ] Contract regenerated, linted, stale check passes.
