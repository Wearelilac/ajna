# P0.2-on-device-acoustic-inference

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`, handoff of `P0.1` (for conventions only; no dependency on its results).

## Purpose

Throwaway experiment answering: can an Expo development build run an acoustic and tone model entirely on-device, inside an ephemeral buffer, within acceptable latency, battery and permission limits on Android and iOS, with provable buffer ephemerality and an acceptable false-trigger rate? Output is a findings note. `M3.1`, `M3.2`, `B3.1` and `W3.1` must not start until it exists.

## What already exists

- The four foundation files, and the `P0.1` findings note (unrelated to this experiment).
- No production code, tables, endpoints, screens or jobs.

## Scope

1. **Native audio path.** Build a minimal Expo development build (not Expo Go) with a native audio stream capture library. Evaluate at least two: the brief's `react-native-ovo` (confirm it exists and is maintained, otherwise record that) and one alternative (for example `react-native-audio-api` or a small custom Expo module). Record which gives raw PCM frames to JS or native code with low latency.
2. **Model packaging.** Package a small audio classifier (open model such as a YAMNet/VGGish-class or a small custom CNN on mel features, converted to ONNX or TFLite) with `onnxruntime-react-native` or TFLite. Record: model size in MB, app size increase, load time.
3. **Ephemeral ring buffer.** Implement a fixed-size ring buffer (default 10 s, 16 kHz mono) held only in memory, overwritten continuously and zero-filled on stop, background and error. Inference reads windows from it and nothing else copies audio.
4. **Latency and battery.** On at least one mid-range Android device and one iPhone, measure: inference time per window (p50, p95), end-to-end sound-to-flag latency, CPU use, and battery drain per hour of a monitor session with the screen on (and with the screen dimmed).
5. **OS limits.** Test and document: microphone permission flow, behaviour on app background, screen lock, incoming call, headset plug/unplug. Document Android foreground-service requirements and iOS background audio limits. Per the approval decision, Feature B is foreground-only; this experiment states whether a limited background mode is realistic, as information for later.
6. **Ephemerality proof (first version).** Implement the first versions of the tests in `00-data-protection-model.md` section 6: import isolation lint, runtime spy on fetch/XHR/WebSocket/filesystem/storage, and a canary pattern test against buffer, storage directories and logs.
7. **False-trigger rate.** Build a nuisance set (TV drama, music, laughter, arguments on television, traffic, kitchen noise, shouting at sports events, children playing) of at least 2 hours total from licensed or self-recorded material. Report triggers per hour at three thresholds. Report the true-positive rate on an acted or licensed distress clip set, stating its size and limits honestly.
8. **Findings note** at `findings/P0.2-findings.md`, including which native libraries were inspected for audio persistence or telemetry.

## Out of scope

- Production UI, consent screens, session lifecycle (`M3.2`).
- Sending flags to a server or any API work (`B3.1`).
- Training a production-quality model. Use an existing open model or a small prototype and be clear about its limits.
- Speech recognition of any kind.

## Contracts used

None read or published. The de-identified flag shape from `00-data-protection-model.md` section 1 is used as the target output object, but no endpoint is called.

## Data model

Client-side only, in-memory:

- `EdgeBuffer { capacitySamples, sampleRate, writeIndex, filled }` (ring buffer, zero-filled on stop)
- `InferenceResult { signature, confidence, windowStartMs }` (transient)
- `DeIdentifiedFlag { signature, confidence, time_bucket, model_version, session_id }` (matches the allow-list, constructed only when a threshold is crossed)

No database, no files, no storage writes except the findings note.

## Rules and behaviour

- Audio exists only inside the ring buffer and the model's input tensor. It is never copied into any structure that outlives the inference call.
- No cloud fallback: if the model fails to load, report "unavailable".
- The only object allowed out of the edge module is a `DeIdentifiedFlag`.
- The prototype shows a visible listening indicator whenever the buffer is active.
- Logs contain counters and timings only. Never samples, features or flag contents beyond the class name.
- Prototype code is throwaway and under `prototypes/p0.2/`. It is never imported by production code.
- Record exact device models, OS versions and library versions.

## Acceptance checks

- [ ] Report which audio capture library was used, and the evidence on whether `react-native-ovo` exists or not.
- [ ] Model size (MB), app size delta (MB) and cold load time (ms) reported.
- [ ] Inference p50 and p95 (ms per window) reported for Android and iOS devices (named).
- [ ] Battery drain per hour reported for each device, screen on and dimmed (percentage points).
- [ ] Ring buffer test: after session stop, buffer reads all zeros (test name and result).
- [ ] Import-isolation lint: fails when a network/fs/storage import is deliberately added to `edge/` (show the failing run) and passes without it.
- [ ] Runtime spy test: zero network, filesystem and storage calls during a 10-minute scripted session with no threshold crossing; only allow-listed flag-sized payloads when a threshold is crossed (report counts).
- [ ] Canary test: pattern not found in heap snapshot after stop, storage directories, logs or outgoing request bodies (report what was scanned).
- [ ] Nuisance set: duration (hours), triggers per hour at three thresholds, and true-positive rate on the distress clip set (with set size).
- [ ] OS limits table written: permission, background, lock, call interruption, per platform.
- [ ] Native libraries inspected for persistence or telemetry, with result per library.
- [ ] Verdict `go`, `limited-go` or `no-go` recorded with any limit quoted (for example "foreground only, 20-minute session cap, Android only").
