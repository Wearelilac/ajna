# P0.1-wearable-ingestion-sim

**Read first:** `00-glossary.md`, `00-stack-and-conventions.md`, `00-data-protection-model.md`, `00-system-map.md`.

## Purpose

Throwaway experiment answering: can Ajna ingest simulated multi-stream wearable payloads, compute a 30-day personal baseline, detect >3 SD deviations reliably, and push the work through BullMQ on free Render/Upstash tiers fast enough for a demo? Output is a findings note with a verdict. Production code for Feature A (`B2.1`, `B2.2`, `M2.1`) must not start until this note exists.

## What already exists

- The four foundation files only. No code, tables, endpoints, screens or jobs.

## Scope

1. **Payload shapes.** Define two or three realistic daily-summary payload shapes (an Oura-style one, a generic one, a minimal one) in `prototypes/p0.1/payloads/`, covering: HRV (RMSSD, ms), skin temperature deviation (°C from personal norm), resting heart rate (bpm), sleep architecture (total, deep, REM, light, awake minutes, efficiency), activity and recovery ratio. Decide one canonical internal shape and write the mapping from each vendor-style shape to it.
2. **Simulator.** Generate 60 days of data for 1,000 synthetic subjects with: personal means and SDs, weekly rhythm, missing days (about 5%), sensor outliers, and injected events (a sustained HRV drop plus resting HR rise in 5% of subjects) with known ground truth.
3. **Baseline computation.** Implement the 30-day baseline (trailing, excluding the current day) in Python (numpy/scipy) with two variants: mean/SD, and median/MAD (robust). Apply the rule that at least 14 valid days are needed.
4. **Deviation detection.** Flag |z| > 3 per metric. Also test a multi-metric rule (two or more metrics beyond 2 SD in the same direction) as an alternative. Measure on the injected ground truth: detection rate, false-flag rate per subject-month, days-to-detection.
5. **PRI draft.** Compute a draft 0-100 Personal Resilience Index from weighted z-scores. Document the formula and check it behaves sensibly on the injected events.
6. **BullMQ throughput.** In a small NestJS or plain Node harness on Render free tier plus Upstash free Redis, enqueue baseline jobs for 1,000 subjects. Record: jobs per second, p95 job latency, Upstash command usage for the run versus the free-tier daily limit, any cold-start delays on Render free tier.
7. **Findings note** at `findings/P0.1-findings.md`.

## Out of scope

- Real wearable vendor OAuth or live API calls.
- Persisting to the production schema, encryption vaults, auth, RLS (`B1.2`, `B1.3`).
- The final PRI weights and UI (`B2.2`, `M2.1`).

## Contracts used

None. This file neither reads nor publishes `openapi.v1.yaml`. The canonical payload shape it recommends becomes an input to `B2.1`, which publishes the endpoint.

## Data model

Throwaway, in `prototypes/p0.1/`:

- `subjects(id, mean_* , sd_*, injected_event boolean, event_start date)`
- `daily_metrics(subject_id, date, hrv_rmssd_ms, skin_temp_dev_c, resting_hr_bpm, sleep_total_min, sleep_deep_min, sleep_rem_min, sleep_light_min, sleep_awake_min, sleep_efficiency, activity_recovery_ratio)`
- `baselines(subject_id, date, metric, mean, sd, n_valid_days)`
- `deviation_flags(subject_id, date, metric, z)`

No real data. Synthetic IDs only.

## Rules and behaviour

- Baseline excludes the day being scored. Missing days are skipped, never zero-filled.
- SD floor: if a metric's SD is below a small epsilon, the z-score is undefined and no flag is raised.
- No flag before 14 valid days.
- Output wording follows the glossary: "deviation flag", "flagged for review". No file or log line says "diagnosed".
- Prototype code lives only under `prototypes/` and is never imported by production code.
- Record exact versions, instance types and dates in the findings note.

## Acceptance checks

- [ ] Canonical payload shape documented, with mapping tests for each vendor-style shape (report number of mapped fields per shape).
- [ ] Simulator reproducible: same seed gives identical output (report the seed and a checksum of the dataset).
- [ ] Baseline computed for 1,000 subjects × 60 days; report runtime in seconds for both mean/SD and median/MAD.
- [ ] Detection quality on injected events: report detection rate (%), false flags per subject-month and median days-to-detection for each rule variant.
- [ ] Recommendation stated for the production rule (mean/SD vs median/MAD, single-metric vs combined), with the numbers that justify it.
- [ ] BullMQ throughput measured: jobs/sec, p95 latency, Upstash commands used versus free-tier limit.
- [ ] Verdict recorded in `findings/P0.1-findings.md` as `go`, `limited-go` or `no-go`, with any limit quoted (for example "max N subjects per minute on free tier").
- [ ] Findings note lists "Gaps found" (anything outside the locked stack).
